# 第一章：项目结构与职责

> 目录表达职责和依赖关系。Spring Boot 没有强制要求唯一的业务目录结构。本文记录当前学习约定，不是所有项目的唯一标准。

路线：[[Spring Boot工程实践学习路线]]

## 本章目标

理解代码应该放在哪里、各层负责什么、业务模块如何协作，能够检查 AI 生成代码的职责与边界。

## 核心结论

- 业务模块在外，技术分层在内；业务包不是 Maven 模块或微服务。
- Controller 衔接 HTTP 与业务，Service 执行规则，Mapper 负责数据库访问。
- 模块通过明确业务入口与数据契约协作。
- 主方法表达流程，内部方法封装细节，不为形式增加接口和对象。
- 技术组件提供能力，业务模块决定如何使用。
- 请求、持久化和响应各有边界；订单保存必要的历史事实。

## 11. 检查 AI 生成代码

1. Controller 是否包含大量业务流程？
2. 跨模块调用是否绕过必要规则？
3. 请求是否允许客户端指定成交金额、买家身份等敏感业务字段？
4. 响应是否意外暴露内部字段？
5. 库存逻辑是否只有查询，没有可靠扣减？
6. 历史订单是否错误依赖商品当前价格？
7. 是否为形式完整增加空接口、无意义子方法和公共工具？
