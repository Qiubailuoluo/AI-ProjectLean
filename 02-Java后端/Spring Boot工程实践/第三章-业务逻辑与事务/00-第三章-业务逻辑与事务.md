## 四组边界

- 方法拆分决定可读性，事务边界决定哪些数据库操作共同生效。
- 事务与并发控制需要配合；加注解不自动防超卖。
- Redis 占位控制当前执行资格，持久化约束守住业务不能重复的规则。
- 回滚处理未提交修改，重试重新执行，补偿用新动作修正已生效结果。

## 复习检查

1. 能否说明事务方法内部吞掉异常可能造成什么问题？
2. 能否区分同类调用不触发事务注解，与已有事务内执行子方法？
3. 能否解释数据库报错会抛异常，而影响行数为零通常需要业务判断？
4. 能否解释 Redis 标识过期后为什么仍可能重复下单？
5. 能否区分失败响应、事务回滚和结果不确定？
