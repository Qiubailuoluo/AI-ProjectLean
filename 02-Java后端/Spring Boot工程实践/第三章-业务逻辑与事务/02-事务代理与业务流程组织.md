# 事务代理与业务流程组织

所属章节：[[00-第三章-业务逻辑与事务]]。

## 主方法呈现流程

主方法描述业务步骤、子方法封装细节是常见写法，不是必须把每一行拆成方法。内部辅助方法可以是 private。

```java
@Transactional
public Long createOrder(CreateOrderCommand command) {
    checkRules(command);
    deductStock(command);
    return saveOrder(command);
}
```

代码为职责示意，省略类定义和依赖；事务由外部经 Spring 代理调用这个业务入口而建立，内部方法无需再次开启事务。

## 同类内部调用的误区

默认代理模式下，未开启事务的 mainFlow 在同一个对象内部直接调用带事务注解的 stepA，不会因 stepA 的注解建立事务。自行 new 出来的对象也不能期待 Spring 自动代理。

但若 mainFlow 本身通过代理开启了事务，内部数据库步骤仍可参与已有事务。内调不触发注解，不等于内部一定没有事务。

主方法有事务时，把慢调用拆成子方法也不会缩短事务。

## 慢外部调用与短事务

```text
编排入口（不启动数据库事务）
  → 必要的外部查询，设置超时
  → 调用另一个 Spring Bean 的事务入口
       → 检查必要规则
       → 可靠扣减库存
       → 保存订单
  → 后续处理
```

外部查询可能过期，事务内仍需保护关键规则。只有存在实际边界需要时才拆编排类与事务类，不要求所有简单 Service 都分两层。

另一种方式是 TransactionTemplate，在流程里明确圈定事务代码块。不要为绕过同类代理问题，优先引入隐蔽的自注入等技巧。

## 为什么缩短事务

扣减库存后等待远程接口，可能持续占用连接并持有锁，让其他请求排队。把远程调用放进数据库事务，也不能让远程副作用随数据库回滚。

必须共同生效的数据库操作放短事务；外部操作的时机、超时、重试和补偿单独设计。
