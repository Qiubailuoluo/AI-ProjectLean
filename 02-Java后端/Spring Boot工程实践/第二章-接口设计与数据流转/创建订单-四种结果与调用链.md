# 创建订单：四种结果与调用链

所属章节：[[00-第二章-接口设计与数据流转|第二章-接口设计与数据流转]] · 结构基础：[[00-第一章-项目结构与职责|第一章-项目结构与职责]]

假设用户已经通过认证。请求为 POST /orders，包含 productId 和 quantity。以下状态映射是当前示例约定。

## 1. 参数不合法

quantity 为 0：

```text
请求 → JSON 转换 → 输入校验失败 → 统一异常处理
                                      ↓
                            400 + INVALID_ARGUMENT
```

不会进入 Controller 方法体中的业务调用，也不会执行下单 Service。JSON 本身不合法，则在更早的转换阶段失败。

## 2. 商品已下架

```text
请求 → 校验通过 → Controller → OrderService
                                  ↓
                         商品业务入口发现已下架
                                  ↓
                           业务异常向外传播
                                  ↓
                         统一异常处理生成响应
                                  ↓
                         409 + PRODUCT_OFF_SHELF
```

正常流程中断，不继续执行后续扣减和保存。若失败发生前已有写入，是否回滚仍由事务设计决定。

## 3. 创建成功

```text
校验通过 → Controller → Service
                         ↓
                检查商品、计算金额
                         ↓
                可靠扣减库存、保存订单
                         ↓
                 正常返回到 Controller
                         ↓
                 201 + SUCCESS + 订单信息
```

在同步创建示例中，成功应表示约定操作已经完成，而非只收到请求。声明式事务若由代理管理，提交通常发生在代理调用返回之前；提交失败不应作为正常成功结果返回。异步受理属于另一种接口契约，尚未展开。

## 4. 数据库访问故障

```text
Service → Mapper → 数据库访问异常
                         ↓
                  向外传播及事务处理
                         ↓
                    统一异常处理
                         ↓
                   500 + INTERNAL_ERROR
```

服务端记录异常堆栈和必要上下文，对外返回适当提示，不泄露底层 SQL 等信息。

需要注意：网络或提交故障可能让调用方无法确定最终结果。不能只根据 500 就认定订单没有生成并盲目重试；幂等与结果确认后续讨论。

## 对照表

| 结果 | 发现位置 | HTTP 响应生成位置 |
| --- | --- | --- |
| 输入错误 | 转换或校验阶段 | MVC 异常处理 |
| 商品下架 | 业务层 | MVC 异常处理 |
| 创建成功 | 业务完成并正常返回 | Controller |
| 数据库故障 | 数据访问或事务提交阶段 | MVC 异常处理 |

认证失败不在本例四条链路内，应结合安全框架失败处理入口理解。统一响应处理与事务回滚是两种职责。
