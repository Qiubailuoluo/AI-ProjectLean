# 第五章：工程规范与质量

路线：[[Spring Boot工程实践学习路线]] · 前置：[[00-第四章-数据存储与访问]]。

## 本章要解决什么

前四章建立了目录、接口、事务和存储的主线。本章关注：代码能运行之后，怎样让别人读得懂、发生故障能定位、换环境能配置、修改行为有验证、依赖变化可控制。

仍然使用商品与创建订单案例，目标是能够判断 AI 提交的代码是否符合业务和工程要求。本章是可独立阅读的基础稿，尚未逐项讨论或在真实 Spring Boot 项目执行，不视为已经掌握。第四章仍保留待阅读、答疑与实践状态，进入新章不代表前章已实践通过。

## 本章的几组区别

- **命名与职责**：好名字不能修复错误分层，错误名字也会遮住已有职责。
- **日志与业务事实**：日志说明程序观察到什么，不能代替订单记录、事务结果或审计机制。
- **配置与业务数据**：连接地址属于环境配置，商品售价属于业务数据；放进 YAML 不代表设计合理。
- **测试与运行**：应用启动成功不等于订单失败时库存正确恢复；Mock 通过不等于真实数据库行为正确。
- **版本托管与引入依赖**：管理版本不等于把库加入应用；升级某个库不等于整个组合兼容。
- **约定与强制要求**：团队风格可以统一，不能把某种目录、命名后缀或固定行数写成框架唯一标准。

## 本次边界

代码、配置与命令均为教学材料。涉及 Spring Boot、JUnit 等的注解、包名、依赖和运行要求，应以实际项目版本核对；文中的官方链接可能默认展示较新的版本，不是要求现有项目升级。没有在本机安装或升级工具，没有连接业务数据库或执行应用测试。

本章先建立合理的工程判断，不展开生产部署、完整监控平台、完整 CI 配置或正式 AI 编程 Skill。第六章 [[00-第六章-部署与运行|部署与运行]] 已按用户安排另行整理，前章的实践状态独立保留；Spring Boot 路线整体结束后，再结合实践形成适用范围明确的编程约束。
