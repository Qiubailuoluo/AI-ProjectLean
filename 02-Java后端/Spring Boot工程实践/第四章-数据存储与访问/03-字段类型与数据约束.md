# 字段类型与数据约束

所属章节：[[00-第四章-数据存储与访问]]。

## 类型先看业务含义

| 数据 | 类型示例 | 注意事项 |
| --- | --- | --- |
| 主键 | BIGINT | 范围按业务确认 |
| 整件商品数量 | INT | 非空与正数分别约束 |
| 金额 | DECIMAL(12,2) | 共 12 位，其中小数 2 位 |
| 名称快照 | VARCHAR(200) | 长度是示例，不是统一标准 |
| 手机号、邮编、业务编号 | 字符串 | 标识不等于参与计算的数字，可能含前导零 |

FLOAT、DOUBLE 是近似数值，金额当前采用 MySQL DECIMAL 与 Java BigDecimal。还需明确舍入方式、计算顺序和保留位数；不能只靠写入数据库时处理多余小数。

另一方案是整数保存最小货币单位，例如 299 元存 29900 分，仍需统一币种、单位、范围及中间运算精度。

## 约束的不同职责

| 声明 | 作用 | 不能误解成 |
| --- | --- | --- |
| NOT NULL | 不允许 NULL | 自动禁止空字符串或负数 |
| DEFAULT | 省略字段时采用约定初始值 | 自动修复任何非法输入 |
| UNIQUE | 值或组合不重复 | 可空列中的 NULL 也只允许一个 |
| CHECK | 检查可表达的字段条件 | 替代所有业务流程规则 |

状态可以按约定默认 CREATED；金额若必须计算，不能为避免报错就默认零掩盖程序遗漏。

```sql
UNIQUE KEY uk_order_user_request (user_id, request_id)
```

表示用户与请求标识的组合唯一，不是两个字段分别唯一。要求每笔记录有标识时还需 NOT NULL；MySQL 唯一索引允许可空列有多个 NULL。

```sql
quantity INT NOT NULL,
CONSTRAINT chk_order_item_quantity CHECK (quantity > 0)
```

CHECK 需要使用支持并实际执行约束的 MySQL 版本；NULL 判断不能只依赖 CHECK，应按要求配合 NOT NULL。

## 多层保障，不机械重复

DTO 检查输入格式与范围；Service 检查权限、业务规则和入口必要前提；数据库用约束兜底。非 HTTP 入口不天然经过 DTO 校验，因此 Service 不能盲信所有输入已经检查。

抽取 validateInput、checkPurchaseRules 是代码组织方式。库存重复查询两次也不能解决并发，最终仍需条件更新等可靠机制。
