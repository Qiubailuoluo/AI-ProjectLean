# AI 编程规范使用说明

版本：0.23 · 更新：2026-11-01

唯一维护源为完整 `07-AI编程规范/` 目录，包含总路由、任务 Skill、共享规范和按需参考。资料按任务加载。不要将完整目录拼接到系统提示或要求每次通读全部文件；常驻项目规则仅保留路由提示，`maintenance/` 不作为默认附件或启动上下文。

## 在仓库型 AI 中使用

把完整目录放在目标仓库中，保留相对路径并打开该仓库。提示 AI：

```text
读取 `07-AI编程规范/README.md`，按当前任务选择适用 Skill 及必要引用资料。
实施前核对现有实现、调用方、版本与生效配置，判断条款是否适用；优先复用契约一致的能力。
发现规范与项目事实冲突、规则过时或信息不足时，说明依据并在授权范围内采用最小可行方案；必要时查阅目标版本官方资料，不机械套用示例。
完成后简述关键判断、实际验证和未验证项；涉及重要条款的偏离时说明理由。
```

工具无法读取完整目录时，提供总 README、匹配的 Skill、相关共用规则及任务所需参考资料。

客户端或 IDE 决定文件读取、Skill 发现及规则加载能力，模型名称本身不决定这些能力。链接存在不代表内容已经加载；接入首次验证时，应核对实际读取的文件与采用的约束。

本目录是共享维护源，当前推荐整包入库后使用上述路由提示，也可将该提示追加到现有项目规则中。不要覆盖目标项目的原有规则。各入口包含跨目录引用，不能将单个 `SKILL.md` 或子目录直接视为独立安装包。原生独立分发需按目标工具打包依赖、改写路径，并校验元数据及安装后发现行为；采用 Agent Skills 标准时，产物目录名须与 `name` 一致。当前未提供此类安装产物。

## 项目记录接入

在目标项目启用项目记录时，先经[项目记录 Skill](common/skills/project-memory/SKILL.md)定位或初始化已有记录体系；不要在本规范目录内保存目标项目的具体任务历史。将实际记录入口及当前参与者的写入目录追加到现有项目规则，不覆盖原规则。并行会话使用不同参与者 ID，其他 AI 目录保持只读，共享文件指定维护者。

可追加提示：先读项目记录索引及本任务记录；其他 AI 的结论只作线索，实施前核对相关证据；仅更新自己的目录和明确归属的共享文件，保留交接入口。临时资料须完成必要归档后再按授权清理。

## 各工具接入

- **ChatGPT Projects**：项目说明保留简短路由；项目资料加入总 README 和常用规则，任务时补充匹配 Skill 与参考。项目资料和项目说明的限制依账户设置而异。[Projects 官方说明](https://help.openai.com/en/articles/10169521-projects)
- **Codex 或其他仓库型编码工具**：在目标仓库打开后使用上面的路径提示。只有设置原生 Skills 入口时才按该工具当前机制配置。
- **Claude Code**：项目 Skill 路径为 `.claude/skills/<skill-name>/SKILL.md`。各技术 Skill 带本域参考，部分也引用 `common/`；Spring Boot Skills 还会跨域引用。原生单 Skill 接入需包含其相对引用或完成适配；否则在仓库会话里显式按根 README 读取。[Claude Code Skills 说明](https://code.claude.com/docs/en/skills)
- **Cursor**：`SKILL.md` 不会作为 Project Rule 自动加载。仓库级自动路由使用 `.cursor/rules/*.mdc` 或 `AGENTS.md`，规则只指向总 README；按任务读取详细文件，避免常驻注入全部规范。[Cursor Rules 说明](https://cursor.com/docs/rules)
- **DeepSeek**：若当前界面可读取仓库，使用根 README 路由；若只能收附件或文本，提供匹配 Skill 和必要参考。功能入口以当前产品界面为准。

各产品采用不同的原生 Skill/Rule 机制。本目录作为跨工具维护源；平台适配应遵循目标工具的入口格式，并保留来源与相对引用。

## 目录路由

- [README.md](README.md)：跨技术域任务路由和共用约束。
- `common/`：跨技术域的代码审查、Git 交付与项目记录 Skill，以及工程底线、代码复用与注释要求；请求防滥用及资源上传下载按任务读取。
- [springboot-change/](springboot-change/README.md)：七份 Spring Boot 任务 Skill、框架参考及两个可选示例。
- [vue/](vue/README.md)：四份 Vue 任务 Skill，分别处理页面、请求状态、路由会话和构建验证；视觉设计及国际化按需读取专题参考。
- [mysql/](mysql/SKILL.md)：MySQL 任务入口和八份数据库专题参考。
- [redis/](redis/SKILL.md)、[minio/](minio/SKILL.md)、[nginx/](nginx/SKILL.md)：各自独立的技术入口与参考；Redis 按需提供结构、Key/Value、缓存一致性及客户端资源专题；Nginx 将限流与连接资源单独加载。

示例按总 README 的[加载约定](README.md#加载约定)选择与迁移；目录结构、依赖、数据库版本和运行方式以目标项目为准。

## 维护与验收

发现规范问题、需要记录优化或评审本规范时，按[维护入口](maintenance/README.md)选择相关内容。新增记录不要求通读历史，普通编码及无发现的例行检查不生成维护日志；综合复审才覆盖全部维护记录，并重新核对当前文件与证据。

原[Skill 编写与审查复盘](maintenance/01-Skill编写与审查复盘.md)作为历史资料保留；各 AI 的独立记录和公共议题分别维护，不继续把全部历史追加进一份长文。记录不自动成为正式规则，也不替代当前授权。
