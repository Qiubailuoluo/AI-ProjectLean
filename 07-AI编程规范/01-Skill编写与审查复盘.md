# Skill 编写与审查复盘

记录日期：2026-10-31。适用范围：维护 `07-AI编程规范/` 的入口、参考、示例及接入说明。普通编码任务不默认读取本文件。

目标：使规范改善 AI 的技术判断、复用和验证行为，控制无关上下文，并避免将特定实现扩展为普遍要求。本次问题属于规范缺陷及潜在误导，不代表已在生产系统造成事故。

## 本次发现与修正原则

| 问题 | 根因与影响 | 修正及防复发要求 |
| --- | --- | --- |
| 文风偏讲解、句子持续扩展 | 依据对话逐段追加，混合解释、条件、要求和例子，降低检索效率 | 使用“适用条件、约束、验证结果”组织条款；删除不改变技术决策的解释，不通过替换口语词制造形式上的严谨 |
| 短 Skill 引用过多、环境核查不裁剪 | 仅关注单文件长度，忽略一次任务的累计加载与循环引用 | 每个链接说明读取条件；复用已读且未变化的内容；证据足够时停止扩展，不设置任意文件数配额 |
| 共享源被误认为独立安装包 | 跨目录相对引用在单独复制后失效 | 区分仓库共享源与安装产物；独立分发须打包引用依赖并在安装位置验证；模型名称不代表客户端具备文件发现能力 |
| Redis 入口宣称支持幂等但正文只覆盖缓存 | 描述范围扩大，实际指导与验证未补齐，产生错误触发 | 入口仅声明已覆盖能力；未覆盖任务依据项目和官方资料处理，不为扩大关键词范围增加不完整承诺 |
| 代码审查被普通合并操作触发，必要检查又受到限制 | 触发条件与执行边界未分别审查 | 专项审查按请求范围触发；只读检查、本地验证及外部操作分别遵循已有授权，避免无依据扩大工作或增加确认步骤 |
| Redis/MinIO 只有判断“需要复用”后才读取复用规范 | 将结论放在核查之前，可能重复建设 | 新增或修改实现代码前检查现有能力；复用依据输入输出、权限、事务与失败契约，不依据名称相似 |
| 将可靠缓存失效直接规定为新建 Outbox | 把目标与一种实现绑定，忽略已有可靠事件链路 | 表达所需恢复与投递保证；优先评估已有机制。仅在选用事务发件箱时要求任务与业务变更同事务提交 |
| 将 Controller–Service–Mapper 分层等同于 MVC | 沿用对话中的概念混用，可能诱导无必要的架构重组 | 核对技术术语；区分表现层模式、技术分层和领域边界，架构名称不产生必建目录 |
| 缓存主题只路由 Redis | 按组件名称拆分，遗漏 Spring Cache、本地缓存及多级缓存的集成行为 | 按实际实现选参考；检查命中是否跳过方法体、授权是否仍执行、Key 隔离、代理生效及提交后失效时机 |
| 唯一临时对象 Key 被列为防重复覆盖措施 | 混淆不同上传之间的唯一性与同一上传凭据的可重放性 | 业务绑定已验证且不可被上传凭据替换的内容；固定版本或受控最终对象，覆盖校验与使用之间的竞态 |
| Nginx 与 MinIO 分别正确，但私有缓存组合约束不足 | 未沿完整请求链检查缓存命中时被跳过的授权环节 | 验证签名到期、篡改、无签名及缓存 HIT 路径；日志不得直接记录含凭据的完整查询串 |
| HTTPS 上游缺少身份校验要求 | 将传输加密误认为已验证目标身份 | 核对证书校验、可信 CA、目标名与 SNI；验证错误证书拒绝路径，不能仅检查 URL 使用 HTTPS |
| 元数据和链接通过后即评估为成熟规范 | 静态格式不能证明规则适用性、实现正确性或上下文收益 | 分别记录静态检查、行为评估及真实运行证据；未经跨客户端实测，不宣称普遍兼容或固定 Token 节省比例 |
| 前端相同字段显示名不一致、组件和样式逐页复制，长流程不断追加补丁 | 仅列出“复用”“校验”等抽象原则，没有说明展示语义、复用边界及何时局部重构 | 核对字段业务含义与页面上下文；在契约一致时复用组件与样式令牌；长页面按职责整理，不设统一行数门槛；前端按需求拦截明确无效输入 |
| 统一接口、设计美学或跨平台要求被写成固定技术选型 | 混淆项目契约与普遍规则，可能强制新增响应包装、组件库、国际化或全平台测试 | 先核对既有接口与设计体系；按需选择开源组件并确认版本与许可证；语言、主题和平台支持范围由产品目标确定 |
| Vue 新增主题与多语言参考，但入口描述未同步；泛化场景直接链接特定中间件 | 只更新正文，忽略发现阶段与跨域路由条件 | 修改能力范围时同步检查入口描述；仅在实际采用相应服务时读取 MinIO、Nginx 等实现参考 |
| 通用请求复用没有区分第三方凭据域，退出清理没有覆盖晚到响应 | 只检查单次调用和同步清空，遗漏跨服务与跨会话边界 | 预签名请求隔离业务凭据与响应解析；异步成功、失败及完成回调都核验当前会话与请求归属 |

对应技术要求维护于[缓存集成](springboot-change/references/SpringBoot-缓存集成.md)、[Redis 一致性](redis/references/缓存读写与一致性.md)、[MinIO 文件生命周期](minio/references/文件生命周期.md)、[Nginx 代理缓存](nginx/references/代理缓存.md)、[代理路径与排查](nginx/references/代理路径与排查.md)及[项目组织](springboot-change/references/SpringBoot-项目组织与共享职责.md)。本复盘记录成因与审查方法，不作为这些技术规则的第二维护源。

## 编写要求

1. **明确增量价值**：每条规则对应已确认需求、具体失败模式或非显然约束。删除模型通常已掌握且不改变决策的常识，以及仅为覆盖更多术语而添加的内容。
2. **明确适用条件**：区分技术事实、强制约束、项目约定、可选机制和示例。使用“必须”“不得”时写明成立条件，不能将单次问题推广到所有任务。
3. **保留核查能力**：要求依据项目代码、实际配置和目标版本判断适用性。发现冲突时允许基于证据调整；既有代码和 Skill 均不自动构成正确性证明。执行要求统一见[规范适用性核查](common/references/工程底线.md#规范适用性核查)。
4. **控制维护位置**：通用要求归 `common/`，技术语义归所属领域，框架集成归框架参考。一个规则保留一个主要维护位置；交叉链接说明组合场景，不复制整套要求。
5. **控制目录增量**：只有触发场景、必要上下文或验证方法明显独立时新增 Skill。局部缺口优先修改现有条款或增加按需参考；维护复盘不进入普通任务的读取链。
6. **检查组合行为**：涉及代理、缓存、事务或外部存储时，沿实际调用链检查被跳过的步骤、提交时刻、授权边界、重复执行及结果未知状态。单个组件的保证不能直接推广到整个链路。
7. **保持输出克制**：交付只说明关键依据、重要偏离、实际验证和未验证项；不要求每次复制整份检查表，不为遵守文档新增无必要的依赖、抽象或测试。

## 验收方法

- **静态检查**：校验 Skill 元数据、名称唯一性、相对路径、章节锚点和示例状态；共享目录复制后检查引用闭合。安装产物需在实际安装位置另行检查。
- **路由评估**：选择应触发、不应触发和跨域组合任务，记录实际读取文件及用途；检查循环读取、重复加载和未覆盖任务的错误匹配。
- **行为评估**：给评估者任务和最小原始材料，避免预先提供预期结论。检查其方案或代码是否维护关键约束，并在修改后复核相关场景；仅生成方案时标记为模拟评估。
- **运行验证**：针对实际改动验证可观察行为和失败路径；资源、配置和运行结果应可追溯。工具或依赖缺失时说明替代检查及未覆盖部分，不能用静态检查冒充运行验证。

| 验收任务 | 关键可观察结果 |
| --- | --- |
| 修改一个 Controller 响应字段 | 选择接口参考；未扩展为数据库、缓存或架构重组 |
| 修复 Mapper XML 动态排序 | 值绑定与动态标识符白名单分开处理，保留必要的权限及范围条件 |
| 调整 Spring Boot 中纯 Caffeine 缓存的容量与 TTL | 选择缓存集成；验证配置、过期与资源影响，未强制引入 Redis 或 Outbox |
| 非 Spring 项目修改本地缓存 | 不假定存在 Spring 代理或 CacheManager，按实际库处理 |
| Vue 页面修改表单字段 | 核对既有组件与接口契约，限定页面改动；不自动引入新的 Store 或组件库 |
| 同一字段在列表与详情显示不同名称 | 核对业务含义；相同语义复用展示映射，确有不同上下文则保留有依据的文案 |
| 多页面重复相同组件、字号与样式 | 核对现有设计系统并复用稳定契约；避免逐页复制或抽出过度通用组件 |
| 修改一个超过千行且流程长期补丁化的 Vue 文件 | 追踪调用链，在需求范围内按职责完成必要局部重构；不按行数机械拆分 |
| Vue 项目使用裸 HTTP 响应和文件下载 | 不强制套用 `code/message/data`，正确处理 HTTP 状态、空响应和文件流 |
| 已有组件库的项目新增表单与主题切换 | 评估现有组件和主题变量；不并列引入第二套库，手动偏好与系统偏好行为明确 |
| 多语言页面增加长文案和动画 | 翻译、区域格式与回退一致；布局可容纳长文案，减少动态效果偏好得到响应 |
| 只改已有 Naive UI 项目的日语回退与系统主题 | 命中国际化参考，沿用既有组件库，不加载无关表单和后端资料 |
| Cloudflare Pages 托管前端使用 S3 预签名直传 | 不假定 MinIO 或 Nginx；直传不携带业务令牌，不按业务 JSON 结构解析存储响应 |
| A 请求未返回即退出并登录 B | A 的晚到成功、失败和完成回调均不能修改 B 的数据、加载状态、错误或会话 |
| Vue 登录后刷新受限页面 | 核对会话恢复与路由守卫，后端权限仍独立生效 |
| Vue 文件直传 MinIO，经 Nginx 下载 | 组合前端请求、对象绑定与代理路由；区分上传成功和业务确认，核对签名与缓存边界 |
| 多租户详情接入已有 Spring Cache/Redis | 复用已有机制；覆盖命中时授权、Key 隔离、事务提交和回滚 |
| 项目已有可靠变更传播机制，要求缓存最终失效 | 核查现有机制的恢复保证，不直接新建第二套失效链路 |
| Nginx 转发 MinIO 私有签名下载并启用缓存 | 授权与到期约束覆盖缓存 HIT，日志不泄露签名凭据 |
| MinIO 上传确认后重用同一上传 URL | 再次上传不能替换业务引用中已验证的内容 |
| 仅审查代码差异 | 发现包含触发条件和代码证据，未自动修改被审查代码 |
| 规范与目标版本行为不一致 | 说明版本证据与调整理由，未为了符合旧条款生成错误实现 |

本次已完成文档静态检查，以及排序防注入、Spring Cache/Redis、Nginx/MinIO 和 Caffeine 配置四类只读模拟评估。上述验收表还包含后续复核用例，不能视为全部执行通过。未完成四类 AI 客户端的真实项目对照测试，也未测量 Token 节省比例。

Vue 增量独立只读评估覆盖日语回退与系统主题、S3 预签名直传、跨会话晚到响应三类任务。评估发现凭据隔离和异步写回约束不够明确，已针对条款修正；该结果仅为文档与方案评估，不构成浏览器或真实接口验证。

后续记录应包含任务、客户端/模型、相关版本、实际读取内容、观察结果及未验证范围。依据实际失败修订最小相关条款，避免把每个反例累积为全局强制流程。
