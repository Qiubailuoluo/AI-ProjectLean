# 请求防滥用与资源边界

适用范围：登录、验证码发送、搜索、批量处理、导出、上传下载或其他公开/高成本接口的基础防滥用。依据实际入口、业务成本和已有网关能力实施，不按客户端是否自称 AI 判断风险。

## 服务端与入口约束

- 核对公网入口、应用直连、对象存储及第三方服务路径，明确限制实际在哪一层生效。前端防抖、按钮禁用、CORS、robots.txt 或客户端自报身份不构成服务端防护。
- 依据业务配置请求频率、突发量、并发、请求体与批次数量上限；分页、查询范围、导出条数、处理时间及存储/带宽配额同样需要边界。先限制输入和成本，再分配昂贵资源；大任务沿用有容量和超时约束的任务机制。
- 公网粗粒度限制可按可信客户端地址实施，敏感业务还需按已认证用户、租户、接口或目标资源约束；登录/验证码发送考虑目标账号与来源，避免单一 IP 误伤共享网络，也避免仅换 IP 即突破账号预算。不使用可任意伪造的请求头决定豁免或身份。
- 多实例部署核对计数范围和一致性；要求全局预算时复用已有共享限流能力，更新须具备所需原子性及过期机制。本地计数不能宣称覆盖全局，不因本条强制引入 Redis。
- 限流拒绝、系统过载与业务失败按接口契约区分。限流通常使用 429，并在可确定时返回重试时间；前端遵守等待提示，采用有上限的重试，禁止拦截器形成请求风暴。幂等与限流分别处理重复业务效果和资源消耗。
- 明确限流存储、验证码服务或其他依赖失效时的处理：高风险操作不能无条件放行；低风险读取按业务可用性选择受限降级。日志记录脱敏的触发规则、拒绝量和资源耗时，并具备调整、回退和误伤排查路径。

## 按风险触发人机验证

- 依据失败频次、异常速率或敏感动作决定是否启用现有或成熟验证服务；不为每次读取和提交强制弹窗。验证码只作为附加信号，不替代身份认证、资源授权、服务端校验或限流。
- 后端使用服务端凭据验证挑战结果，按供应商协议检查有效期、重复使用及适用的站点/动作约束；不接受前端的“验证通过”布尔值。失败、到期或已消费凭据需重新取得，验证服务调用也须有超时和资源限制。
- 前端提供验证中、失败、重试及可访问的反馈，保留可恢复输入；挑战有效期与业务提交时序协调，避免自动循环提交。验证组件私钥不得进入浏览器产物。
- 自动化使用独立环境及供应商测试凭据；测试配置由服务端环境控制，发布检查确保生产不会接受测试凭据或公开绕过开关。

## 验证与能力边界

在受控环境以有限请求验证阈值、突发、并发、多实例、伪造转发头、账号/IP 变化、429 反馈和恢复；涉及验证码时覆盖缺失、伪造、过期、重放及验证依赖故障。负载测试需明确授权和停止条件，不对真实服务自动发起攻击式流量。

应用和反向代理限制不能保证抵御耗尽公网带宽的大规模攻击；有此风险时使用托管入口已有的防护及告警能力。实际采用 Nginx 且调整速率、突发或并发限制时，读取[限流与连接资源](../../nginx/references/限流与连接资源.md)；涉及转发头、超时或代理配置发布时，再读[代理路径与排查](../../nginx/references/代理路径与排查.md)。涉及文件成本控制时，读[资源发布与上传下载](资源发布与上传下载.md)。
