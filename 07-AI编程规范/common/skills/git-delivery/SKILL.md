# Git 分支与变更交付

先核对当前仓库、工作区、分支、目标基线及项目约定；只处理本任务范围内的改动。用户已明确的流程和工具要求优先，不由本 Skill 推定提交、推送、合并或发布授权。

- 开始新功能、创建分支、整理提交或推送时，读取[Git 分支与提交](../../references/Git分支与提交.md)。
- 工作区包含本地启动/调试适配时，读取[本地运行配置与提交隔离](../../references/本地运行配置与提交隔离.md)，先区分共享变更与仅本地内容。
- 撰写或更新 PR/MR、交接及较复杂提交的正文时，读取[变更描述与验证](../../references/变更描述与验证.md)。仅改提交标题不加载此参考。
- 明确要求代码审查或按项目流程需评审差异时，组合[代码审查](../code-review/SKILL.md)；普通提交不自动触发全仓安全审计。

交付时说明实际分支、提交及推送/PR 状态；执行成功的本地命令不证明远端已更新。已有授权直接沿用，只有当前动作缺少必要授权或关键目标不明时才澄清。
