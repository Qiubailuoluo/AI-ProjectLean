# 规范维护区

这里是**维护规范的 AI 自己写的记录**：改了什么、为什么改、发现了什么、还差什么。写代码任务不读取本目录。目标业务项目的任务历史，留在该项目自己的记录里。

## 文件与归属

| 路径 | 用途 | 谁写 |
| --- | --- | --- |
| [CHANGELOG.md](CHANGELOG.md) | 每个版本改了什么、为什么 | 任何 AI 追加，条目末尾署名 |
| [issues.md](issues.md) | 已发现但未处理的问题 | 任何 AI 追加或更新状态，署名 |
| [regression-tasks.md](regression-tasks.md) | 固定回归任务 | 指定维护者 |
| [扩展指南.md](扩展指南.md) | 新增 Skill、写作规范、粒度取舍 | 指定维护者 |
| `agents/<actor-id>/YYYY-MM-DD-主题.md` | 某个 AI 的独立发现、方案、验证过程 | **只有该 AI 写**，其他 AI 只读 |
| `shared/YYYY-MM-DD-议题.md` | 需要多方讨论或用户确认的议题 | 指定维护者汇总 |
| [archive/](archive/) | 历史复盘原文 | 只读 |

## 约定

1. **写入门槛**：只记有实质变化或新发现的内容。无变化的例行检查不记流水账。
2. **每个 AI 一个 ID**：格式 `<工具>-<模型>-<序号>`，如 `cursor-claude-a01`、`codex-a01`。并行的同模型用不同序号。跨会话继续写入，要有明确归属或用户转交。
3. **各写各的**：个人记录进自己的 `agents/<id>/`。公共的结论回写 CHANGELOG、issues 或 `shared/`，不在个人记录里重复。
4. **单一规则来源**：技术要求只写进所属 Skill 或 reference。本目录只写“改了哪里、为什么”，不复制规则正文。
5. **版本号**：改 Skill、reference、结构时递增，同步更新 `00-使用说明.md` 顶部的版本。
6. **改完先校验**：运行 `python3 tools/check.py`，错误清零再记录。
7. **状态词**：`待处理` → `进行中` → `已完成（静态检查）` → `已验证（回归任务）`。静态检查通过不等于已验证。
8. **记录不是授权**：计划和建议不构成修改、推送、删除的授权，以当次用户指令为准。历史记录只提供线索，采信前核对当前文件和证据。
