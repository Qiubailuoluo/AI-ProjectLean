# 规范维护与评审

仅记录本规范的具体问题、优化建议、讨论决定及验证依据。普通编码不加载本目录；目标业务项目的任务历史留在其自身记录体系中。

## 何时读取与记录

| 任务 | 读取范围 | 写入条件 |
| --- | --- | --- |
| 普通编码、咨询或新会话启动 | 不读取本目录 | 不生成维护日志 |
| 发现问题或提出优化 | 当前问题涉及的正式文件；必要时按路径、主题或问题标识搜索相关记录 | 在自己的目录记录具体触发、影响、证据及最小建议；允许标记待核实 |
| 补充已有议题 | 相关议题及本次需要核对的来源 | 补充新证据或状态，不重复复制既有报告 |
| 专项评审 | 评审范围内的正式文件及相关记录 | 记录有价值的发现或必要验证结果 |
| 综合复审 | 先列清单，再分批覆盖全部维护记录及对应的当前规范 | 汇总仍有效的问题、已解决项、冲突、重复及优化结论；未读或未验证项明确列出 |

- 写入前只核对本目录约定、目标文件和归属；相关记录可用定向搜索定位，不为去重通读全历史。无相关旧记录时可直接新建，信息不足的内容标为假设。
- 同一会话中未变化的约定和资料直接复用。综合复审也不把全部正文一次拼接进上下文；按议题分批核对并保留来源定位。
- 不按轮次、天数或每次修改强制建记录。仅有例行操作、无新发现或无新增证据时，不添加流水账。

## 目录与归属

- `01-Skill编写与审查复盘.md`：迁入的历史原文，仅修复相对链接。保留历史作者及验证限制，不将其归入某个 AI 的个人目录；后续记录进入对应议题或参与者目录。
- `agents/<actor-id>/YYYY-MM-DD-主题.md`：各参与者的独立发现、方案和验证。参与者 ID 不仅由模型名决定；并行同模型使用不同 ID，跨会话继续写入须有明确归属或用户转交。
- `shared/YYYY-MM-DD-议题.md`：需要共同讨论或用户确认的议题。指定维护者汇总并链接原记录，区分用户意见、各 AI 建议和已确认决定，不按发言轮次建文件。
- 各 AI 仅维护自己的目录；其他参与者记录只读。共享文件由指定维护者更新，归属未知时在自己的目录提出建议；用户可调整维护权。日期用于定位，不代表结论正确或优先级更高。

记录按需写明：参与者、日期、范围/规范版本、状态、触发与影响、证据位置、建议或决定、实际验证及未验证项。问题核实、修订授权、实施完成与验证通过分别表达；不保留冗长推演、完整聊天或敏感数据。

历史记录只提供线索。采纳结论前核对当前规范和目标版本；建议不自动生效，过去的计划、讨论和评估不产生修改、部署或删除授权。技术要求回写所属 Skill 或参考，维护记录不成为第二套规则来源。
