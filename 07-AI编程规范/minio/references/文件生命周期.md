# MinIO 文件生命周期与业务绑定

适用范围：应用通过 MinIO 或 S3 兼容对象存储上传、确认、访问、替换和回收文件。实施依据包括目标服务发行版/版本、S3 API 支持范围、SDK 版本、bucket 策略和对象版本配置；能力须按目标环境核验。

## 对象身份与业务元数据

- 对象引用由项目配置的存储域、bucket、object key 及适用时的 version ID 组成；实际端点通过受控配置解析。预签名 URL 是有期限的访问凭据，不是持久对象标识。
- object key 由服务端按项目规则生成，并与用户或租户的授权范围关联。客户端文件名仅作为展示元数据，不直接作为唯一键或授权依据。
- 关系数据库保存业务记录与对象引用，不复制对象内容。记录字段按查询和恢复需求确定，通常包括 bucket/key、可选 version ID、归属范围、生命周期状态、大小、校验摘要、检测出的媒体类型及时间信息。
- 业务绑定须核对调用主体、对象归属、用途、上传意图和当前生命周期状态。对象存在本身不构成绑定授权。

## 上传与确认

1. 服务端创建受授权范围约束的上传意图，生成不可预测或具备冲突防护的临时 object key，并记录允许的大小、用途、期望类型和有效期。具体状态名由项目定义。
2. 直传场景签发仅限目标对象、操作方法、必要请求头和短期有效期的预签名凭据。预签名 PUT 通常可在到期前重复覆盖同一对象；唯一临时 Key 仅隔离不同上传，不阻止同一凭据再次覆盖。
3. 客户端上传完成后，服务端通过对象元数据查询等可信机制核实 key、实际大小及可获得的校验信息。客户端成功响应和 `Content-Type` 声明不作为文件内容验证结果。
4. 按风险校验文件签名/实际格式、恶意内容、配额和业务约束。多段上传或加密可能影响 `ETag` 含义；不得将 `ETag` 一概解释为整个文件的 MD5。
5. 校验与业务引用必须绑定同一不可被上传凭据替换的内容：使用已验证的固定 version ID，或受控复制到客户端无写权限的最终 Key。复制源须固定版本或采用条件保护；无法固定源时，先生成最终对象再验证其内容。后续读取使用同一对象身份，避免校验后覆盖竞态。
6. 验证通过后，按项目事务边界建立业务引用。暂存、确认和绑定状态应支持恢复；重复确认应幂等，数据库失败时保留对象清理或重新绑定路径。

后端代理上传应使用有界流式处理，关闭输入流和对象响应资源，并限制并发、大小和处理时间。大文件直传应配置未完成 multipart upload 的回收策略；经 Nginx 转发时同步检查请求体、缓冲和超时配置，参见 [Nginx Skill](../../nginx/SKILL.md)。

## 下载与访问控制

- 私有对象默认保持私有。每次访问均依据业务资源检查用户/租户权限，再由后端转发对象流或签发短期、限定对象和操作范围的下载凭据。
- 预签名 URL 具备持有者可用的访问能力，应按凭据处理；限制有效期和权限，避免写入日志、工单、分析事件或可被第三方读取的页面引用。
- 上传文件的响应类型、下载文件名和浏览器内联展示按内容风险设置。客户端元数据不直接用于安全决策；主动内容按项目策略隔离或强制下载。
- 私有内容经 Nginx 缓存时，授权与有效期检查必须覆盖缓存命中路径；具体要求见[代理缓存](../../nginx/references/代理缓存.md)。

## 替换、删除与恢复

- 替换文件时，为新内容建立独立对象身份；新对象验证并完成业务绑定后，再按引用关系处置旧对象。数据库记录更新与对象操作不是同一事务，流程须支持部分失败恢复。
- 删除分为业务解绑、逻辑状态变更和对象物理删除。共享对象、并发引用及重试均须纳入判定；删除任务应允许安全重放并记录最终结果。
- 生命周期规则、版本控制和对象锁可能使删除产生删除标记、保留旧版本或拒绝物理删除。启用版本控制时，需明确业务记录绑定最新版本还是固定 version ID，并制定旧版本与删除标记清理规则。
- 对象版本控制不等同于独立备份。恢复方案应覆盖对象内容、数据库引用、版本信息、凭据/密钥和生命周期配置，并在隔离环境演练。
- 定期核对未绑定对象、过期上传意图、失败删除和未完成 multipart upload；自动清理规则不得删除仍可能完成绑定的对象。

## 验证

验证上传超限、内容不符、重复确认、确认后覆盖、数据库写入失败、私有越权、预签名到期、对象替换部分失败、版本删除和清理重试。记录目标服务与 SDK 版本、实际校验方式、最终业务引用及未覆盖情形。
