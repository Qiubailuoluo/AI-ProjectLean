# MySQL 慢查询诊断与优化

适用：定位高耗时、高频或高资源 SQL。优化前确认目标服务器版本、负载窗口、最终 SQL、绑定参数和数据分布。

## 诊断

- 使用慢查询日志、Performance Schema 或 `sys` 汇总识别重复 SQL、调用次数、总耗时、平均/分位耗时、扫描行数和返回行数；问题排序应综合频率、总成本和单次延迟。
- 慢查询日志阈值、输出目标、采集期限、轮转、保留和访问权限按环境配置。日志可能包含 SQL 字面值或敏感数据；general log 仅在受控诊断窗口启用。
- 对 ORM/XML 等生成的 SQL 核对最终文本、实际参数、动态条件、分页和调用频率；方法名与模板不足以还原真实负载。
- 保存优化前证据，包括 SQL 与参数分布、数据量与分布、执行计划、扫描行数、延迟、并发、CPU/I/O、临时表及环境版本；日志和样本应脱敏。

## 优化

- 基于证据提出单一可验证假设，再调整索引或 SQL；避免一次引入多个变量、强制索引或放大服务器参数来掩盖根因。
- 优化目标包括减少无效扫描、回表、排序、重复调用和传输数据。分页应具备稳定排序；深 OFFSET、N+1 查询和全量读取按实际访问模式评估。
- 在代表性数据和可比负载下对照正确性、p50/p95 延迟、吞吐、资源、读写成本及执行计划。小样本、空缓存或单次请求不足以形成性能结论。
- 高风险 SQL、索引或参数变更应在隔离环境验证；生产观测与变更遵循目标项目的授权和发布流程。

官方参考：[慢查询日志](https://dev.mysql.com/doc/refman/en/slow-query-log.html)、[mysqldumpslow](https://dev.mysql.com/doc/refman/en/mysqldumpslow.html)、[EXPLAIN](https://dev.mysql.com/doc/refman/en/explain.html)。
