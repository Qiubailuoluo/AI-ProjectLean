# MySQL 数据建模与约束

适用范围：新表设计、字段与约束变更、关系建模或历史数据语义调整。模型设计依据目标 MySQL 版本、存储引擎、字符集、排序规则和 SQL mode。

## 约束

- 从业务不变量、读写路径、数据规模、增长率、保留期和数据归属建模；默认保持关系清晰。反规范化、分区和 JSON 字段须由查询、写入或演进需求支撑。
- 字段类型应覆盖允许范围并控制存储成本。金额使用精确数值并定义精度、舍入和币种；时间定义时区与精度；字符串明确长度、字符集和排序规则。字段语义不得依赖隐式类型转换或环境默认值。
- 对必填、范围、唯一性和引用完整性评估数据库约束。唯一键符合业务作用域与 NULL 语义；应用层查询后写入不足以保证并发唯一。
- 明确主键生成、稳定性和宽度。InnoDB 二级索引携带主键值，宽主键会扩大二级索引；不强制使用自增或 UUID，按分布式生成、排序和索引局部性要求选择。
- 外键、检查约束和唯一约束按业务完整性、删除生命周期及版本能力选择。未采用数据库约束时，应明确由何种事务、任务或审计流程保障完整性。
- 交易、审计等历史事实按业务要求保存必要快照；当前关联记录不足以还原历史时点的名称、价格或状态。
- 删除、软删除、归档和保留期限应说明对唯一键、查询条件、恢复及隐私要求的影响。仅为有依据的业务需求创建字段或表。

## 验证

验证 DDL 与目标版本语法、字段边界、NULL/默认值、约束冲突、字符集/排序规则及既有数据兼容性。记录数据迁移、回填和失败恢复方式；建表成功本身不构成模型正确性的充分证据。
