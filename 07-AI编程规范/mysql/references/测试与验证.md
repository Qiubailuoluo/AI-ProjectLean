# MySQL 测试与验证

适用：新增或修改 SQL、约束、迁移、事务行为、并发逻辑或查询性能验证。

## 测试边界

- 单元测试用于验证应用分支和参数组装；真实 MySQL 集成测试用于验证 MySQL SQL、类型转换、约束、隔离级别、锁、事务及迁移行为。Mock 或 H2 不构成上述数据库行为的验证证据。
- 测试实例应匹配目标 MySQL 版本、引擎、字符集/排序规则、SQL mode、时区及关键配置。使用容器或共享测试库时，核实实际连接地址与隔离策略。
- 数据准备使用独立 schema、事务或唯一测试标识；清理只作用于测试资源。测试失败、超时或并发时也要验证清理与重跑安全。
- 并发测试使用独立连接和事务并控制交错点；全部事务结束后核对最终数据、约束与副作用。异常或返回码断言不足以证明并发结果。
- 迁移测试覆盖空库初始化、从受支持旧版本升级、代表性既有数据、重复部署/失败恢复及新旧应用兼容。破坏性变更在隔离副本和代表性数据上评估。
- 性能测试采用有代表性的数据量、分布、参数及并发，并固定环境与采样方式；对照正确性、延迟、吞吐、扫描量、资源和写入成本。

## 锁失败与重试

- InnoDB 死锁通常回滚整个事务；锁等待超时默认通常只回滚当前语句，实际结果须结合 `innodb_rollback_on_timeout`、驱动及应用事务管理核实。不能把两者当作相同失败后继续提交剩余写入。
- 仅对已识别且业务允许重放的临时失败有限重试；需要原子恢复时先结束失败事务，再以新事务重放整个业务单元，并设置次数、退避及总时间预算。核对外部副作用和幂等边界，避免每层重试相乘或在已失效事务内只重试最后一条 SQL。
- 使用独立连接构造死锁与等待超时，核对最终数据、事务结束、连接归还和重试耗尽结果；Mock 异常不证明真实回滚范围。

参考：[MySQL 8.4 InnoDB 错误处理](https://dev.mysql.com/doc/refman/8.4/en/innodb-error-handling.html)。以目标版本和实际配置为准。
