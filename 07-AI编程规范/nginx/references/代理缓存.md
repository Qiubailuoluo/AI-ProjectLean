# Nginx 代理缓存

适用范围：使用 `proxy_cache` 缓存上游 HTTP 响应。规则依据目标 Nginx 版本、发行版、构建模块和响应契约确定。

## 缓存边界与 Key

- 仅缓存响应契约明确、允许跨请求复用的资源。认证结果、租户数据及个性化响应不得在共享缓存中串用。
- Cache Key 应覆盖所有影响响应内容的维度，包括协议、主机、路径、查询参数及适用时的租户、语言或内容协商条件。Key 省略任一维度都可能造成错误复用。
- 认证或 Cookie 会影响响应时，应默认绕过读取并禁止写入；若需按用户分区缓存，须评估权限撤销、身份轮换、Key 基数和容量风险。
- 请求头 `Authorization`、`Cookie` 与响应头 `Set-Cookie`、`Vary`、`Cache-Control` 的处理须与代理缓存策略一致。源站缓存头和 Nginx 配置的优先关系按目标版本核验。
- MinIO/S3 私有预签名 URL 的身份凭据可能位于查询串。缓存命中不访问源站，可能绕过源站的签名到期校验；即使 Key 保留完整签名参数也不能单独解决此问题。默认对该类请求同时绕过读取和禁止写入。需要缓存私有内容时，须确保每次请求在命中缓存前完成有效验签或授权，并以受控对象身份与版本定位内容；不得删除签名参数合并 Key 后直接共享响应。

## 读取、写入与有效期

- `proxy_cache_bypass` 控制是否绕过缓存读取；`proxy_no_cache` 控制响应是否写入缓存。涉及个性化或授权数据时，同步定义两类条件，避免只绕过读取仍将响应写入共享缓存。
- 按响应类型设置缓存状态码和 TTL。对过期数据可用范围、源站不可用时是否提供 stale 响应、热点回源合并及响应头更新定义明确策略。
- 缓存目录、`keys_zone`、`max_size`、非活跃清理、临时磁盘和 inode 使用量均纳入容量监控。缓存失效或更新应按实际 Key 与配置规则执行。
- `proxy_cache_purge` 等清除能力依版本、发行版和模块而异；实施前确认目标构建支持情况及该指令的授权条件。

## 验证

验证匿名与认证请求、不同租户/语言、查询参数变化、源站更新、TTL 到期、绕过与禁止写入路径。私有链接额外验证缓存 HIT 时的无签名、篡改、过期与授权撤销行为。检查缓存状态、Key 隔离、响应体和响应头；确认无跨身份复用及源站故障时的预期行为。
