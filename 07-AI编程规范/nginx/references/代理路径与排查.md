# Nginx 代理路径与请求排查

适用范围：反向代理、路径映射、请求头、上传限制、超时或上游故障变更。指令行为以目标 Nginx 版本、构建模块及生效配置为准。`proxy_cache` 规则见[代理缓存](代理缓存.md)。

## 路径匹配与 URI 映射

- 核对虚拟主机选择、`location` 匹配、`rewrite`、`proxy_pass`、应用上下文及上游路由。Nginx 的 `location` 使用规范化 URI 匹配；精确匹配、最长前缀和正则匹配顺序会影响最终配置块。
- 对普通前缀 `location` 且无 `rewrite` 或变量改写的配置，`proxy_pass` 携带 URI 时会以该 URI 替换匹配前缀；不携带 URI 时通常向上游传递原请求 URI。其他配置形态按目标版本文档和实际配置判断。

| 配置 | 上游收到的 URI |
| --- | --- |
| `location /api/ { proxy_pass http://app/; }` | `/api/orders` 映射为 `/orders` |
| `location /api/ { proxy_pass http://app; }` | `/api/orders` 保留为 `/api/orders` |

- 日志应能区分客户端路径、规范化路径、命中配置及上游状态与耗时。`$request_uri` 包含查询串；涉及预签名 URL、令牌或敏感参数时，记录脱敏路径与请求 ID，不直接记录完整 URI。
- 反向代理至 MinIO 或其他签名 URL 服务时，上游 Host、规范化路径和查询串应与签名请求一致。Host 或 URI 改写可能导致签名校验失败；按需组合 [MinIO Skill](../../minio/SKILL.md)。

## 转发头与信任边界

- `Host`、`X-Forwarded-For`、`X-Forwarded-Proto` 和 `Forwarded` 的上游值按部署拓扑定义。不得直接信任公网请求自带的身份、客户端地址或协议声明。
- 明确哪些代理地址可信，并配置边界处的覆盖、追加及解析规则；应用仅信任来自配置代理链的转发信息。代理头不承担业务认证或资源授权。
- `Host` 可影响绝对链接、租户路由和签名校验。按允许的主机名配置虚拟主机与上游值，不将任意请求头用于安全决策。
- HTTPS 上游须核验可信 CA、证书链及目标名，配置 `proxy_ssl_verify`、`proxy_ssl_trusted_certificate` 和适用的 `proxy_ssl_name`；需要 SNI 时启用 `proxy_ssl_server_name`。`proxy_pass https://...` 本身不启用证书校验。验证正确证书可用、错误证书被拒绝。

## 超时、重试与请求体

- 分别设置连接、请求发送、上游响应读取及客户端超时，并与应用、数据库和外部依赖的超时预算协调。`proxy_read_timeout` 等读取超时表示相邻读操作间隔，不是整个响应的总时长上限。
- `proxy_next_upstream` 可在配置条件下将请求转发到其他上游。非幂等请求在请求已发送后的重试须单独审查；不得在未确认幂等性时启用相应重试行为。
- 上传限制须按实际流量路径在 Nginx、应用和存储侧协调设置，核对各层能力与限制；直传大小策略及确认边界见[资源发布与上传下载](../../common/references/资源发布与上传下载.md)。`client_max_body_size` 超限会在代理层返回 413；请求缓冲可能占用内存或临时磁盘。直传 MinIO 时确认流量是否经过 Nginx。
- WebSocket、SSE、流式响应和大文件传输应单独核对协议升级、缓冲、连接时长及资源限制；普通 JSON 代理配置不覆盖这些场景的专用要求。

## 配置发布与定位

- 检查所有 `include` 文件和实际生效配置。`nginx -t` 用于语法与引用检查，不构成上游、授权或业务行为验证。导出完整配置前须移除凭据和内部地址。
- 配置重载前执行目标环境语法检查；重载后确认工作进程、监听端口及上游状态，并验证代表性请求。按项目流程保留可恢复的上一版配置。
- 使用应用直连与外部入口对照定位 404、401/403、413、502/504。结合命中的 `location`、上游状态、耗时、请求 ID 和应用日志区分代理、认证、应用及依赖故障。
