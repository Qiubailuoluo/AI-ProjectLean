# 限流与入口约束

适用：登录、验证码发送、搜索、批量处理、导出、上传下载等公开或高成本接口的基础防滥用。依据实际入口、业务成本、已有的网关能力实施。不按"客户端是否自称 AI"判断风险。人机验证见[人机验证](人机验证.md)。

## 在哪一层生效

- 核对：公网入口、应用直连、对象存储、第三方服务的路径。明确限制实际在哪一层生效。
- 前端防抖、按钮禁用、CORS、robots.txt、客户端自报身份，都不是服务端防护。

## 限制什么

- 依据业务配置：请求频率、突发量、并发、请求体大小、批次数量上限。
- 同样需要边界的还有：分页、查询范围、导出条数、处理时间、存储和带宽配额。
- 先限制输入和成本，再分配昂贵的资源。大任务沿用有容量和超时约束的任务机制。

## 按谁限制

- 公网的粗粒度限制，可按可信的客户端地址。
- 敏感业务，还要按：已认证的用户、租户、接口、目标资源。
- 登录和验证码发送，考虑"目标账号 + 来源"。避免单一 IP 误伤共享网络，也避免换个 IP 就突破账号预算。
- 不用可任意伪造的请求头决定豁免或身份。

## 多实例

- 核对计数的范围和一致性。
- 要求全局预算时，复用已有的共享限流能力，更新要有所需的原子性和过期机制。
- 本地计数不能宣称覆盖全局。不因本条强制引入 Redis。

## 拒绝与重试

- 限流拒绝、系统过载、业务失败，按接口契约区分。
- 限流通常用 429，能确定时返回重试时间。
- 前端遵守等待提示，使用有上限的重试。禁止拦截器形成请求风暴。
- 幂等和限流分别处理：一个管重复的业务效果，一个管资源消耗。

## 依赖失效

- 明确限流存储、验证码服务等依赖失效时怎么处理。
- 高风险操作不能无条件放行。低风险读取，按业务可用性选择受限的降级。
- 日志记录脱敏的触发规则、拒绝量、资源耗时。要能调整、回退、排查误伤。

## 验证

- 在受控环境，用有限的请求验证：阈值、突发、并发、多实例、伪造转发头、账号和 IP 变化、429 反馈、恢复。
- 负载测试要有明确授权和停止条件。不对真实服务自动发起攻击式流量。

## 能力边界

应用和反向代理的限制，保证不了抵御耗尽公网带宽的大规模攻击。有此风险时，使用托管入口已有的防护和告警。

相关 Skill：采用 Nginx 并调整速率、突发、并发限制时，使用 `nginx-proxy`，读「限流与连接资源」。文件成本控制，使用 `file-upload-download`。

参考：[OWASP API 资源消耗风险](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/)。
