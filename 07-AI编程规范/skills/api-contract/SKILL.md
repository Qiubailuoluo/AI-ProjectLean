# 接口契约

先找项目已有的契约来源（OpenAPI 文件、接口文档、已有 Controller 与前端请求层），沿用其命名、错误结构和版本策略；没有时才按下列规则新建。

## 核心规则

**流程**
- 契约先于实现：接口变更先更新契约，再改后端和前端，两侧以同一份契约为准。
- 联调不一致时，以实际请求与响应为准逐字段核对，不只依据前端类型或后端注解推断。

**方法与状态码**
- `GET` 不改变状态；`PUT`、`DELETE` 保持幂等；`POST` 用于创建或非幂等动作，需要安全重试时加幂等键。
- 状态码语义保持一致：400 参数错误、401 未认证（须带 `WWW-Authenticate`）、403 无权限、404 不存在、409 冲突、429 限流、5xx 服务端故障。新接口默认不用 200 包装失败；项目已有统一响应体约定时，沿用并在契约中写明。
- 错误体统一结构：错误码、可读信息、请求标识（用于排查）、字段级错误列表；不暴露堆栈、SQL、内部路径。

**分页与数据类型**
- 分页写明参数、默认值、`size` 上限、默认排序；排序要稳定（加唯一列兜底），避免翻页重复或漏项。
- 时间用 ISO 8601（UTC）；金额用字符串十进制或最小单位整数；超出 JS 安全整数范围的 ID 用字符串。
- 长耗时操作用异步模式：返回 202 与任务标识，再提供状态查询。

**兼容性**
- 新增可选字段、新增接口属于兼容变更。删除或改名字段、改类型、收紧校验、改变语义，属于破坏性变更，需要版本或过渡期，并先查清所有调用方。
- 枚举新增值要考虑旧客户端的处理方式（未知值的降级）。

**文档**
- 每个接口写明鉴权要求、请求与响应示例、主要错误场景；示例用虚构数据，不含真实账号、密钥或个人信息。

## 验证

契约变更后，用实际请求核对状态码、字段、分页边界和错误体，并检查前端请求层是否同步；仅文档更新不算已验证。
