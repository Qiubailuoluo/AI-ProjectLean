# 部署路径与配置契约

适用：搬移 Compose 或环境文件、改构建 context、改前端环境目录、整理部署脚本。目录归属见[项目目录与文件归属](项目目录与文件归属.md)。仅在项目使用对应工具时适用。

## Compose 与环境文件

- 搬移前核对：启动的工作目录、`-f`、`--project-directory`、`--env-file`、服务的 `env_file`、构建 context、挂载源。
- 插值文件，不等于自动注入容器的环境文件。默认查找和相对路径的解析，按实际版本验证。
- 移动 Compose 文件，可能影响默认的项目标识，以及由它派生的网络和卷名称。核对已有的数据卷、挂载、权限、服务地址。
- 启动了空卷，不要误报成"数据丢失"或"迁移完成"。不自动删除旧卷，不执行清库来修复路径问题。

## 构建 context

- Dockerfile 的位置，不决定 `COPY` 的根目录。构建 context 才决定能访问哪些文件。
- `.dockerignore` 放在对应 context 的根目录，或按工具支持用 Dockerfile 专用的忽略文件。`.gitignore` 代替不了它。
- 排除：密钥、临时资料、无关记录、大文件。不用 `COPY . .` 把整个工作区不加筛选地打进镜像。

## 前端环境文件

- 默认位置，与构建器的 root、环境目录选项、模式有关。
- 以 Vite 为例：改 `envDir`，要同步核对脚本和 CI，不能只移动 `.env`。
- 浏览器构建变量，仍不能承载服务端密钥。

## 验证与交付

- 明确唯一的、或有意支持的启动方式。同步 README、脚本、CI、相对引用。
- 在预期的工作目录和构建入口，核对：配置实际解析的值、构建范围、挂载结果。
- 配置展开可能暴露密钥。不直接保存或回传完整的敏感输出。
- 按影响验证：构建、启动、反向代理、环境生效、持久数据路径。静态配置检查，证明不了真实部署成功。
- 没有目标环境时，明确未验证的项。不因整理目录自行部署。
