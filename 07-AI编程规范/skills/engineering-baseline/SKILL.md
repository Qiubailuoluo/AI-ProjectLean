# 工程底线

适用于所有代码变更。项目事实（现有实现、版本、生效配置、已有约定）高于本规范；冲突时以事实为准并说明冲突点，不机械套用。

## 核心规则

**实施前**
- 先查现有实现、调用方、共享组件和测试，再动手；契约（输入输出、权限、失败语义、事务）一致才复用，名称相似不算。
- 新增依赖、抽象、接口前，说明现有机制为何不够。变更范围限于任务所需，不顺手重构、不格式化无关文件。
- 规范里的目录、技术、业务名（订单、库存等）只是示例，不是目标项目事实。

**实施中**
- 身份、权限、价格、状态等权威结论由后端或可信来源决定；前端隐藏、请求自报字段、客户端提交的最终结果都不可信。
- 对外输出只含需要的字段；自动绑定和序列化不得暴露内部字段。
- 失败不得被吞掉后报告成功；区分未执行、失败、处理中、结果不确定；超时不等于未执行。
- 可能被重试或重复投递的操作要有幂等或结果确认策略；回滚、重试、补偿各自说明作用范围。
- 密钥、令牌、密码、带签名的完整 URL 不写入仓库、日志或交付说明；外部输入进日志要限长并处理换行。
- 注释只写代码表达不了的内容：设计依据、不变量、契约、单位边界、并发约束、副作用。不逐行翻译代码；行为变了同步改注释。

**交付前**（详见[完成前自检](references/完成前自检.md)）
- 分别说明静态检查、构建、测试、真实运行各执行了什么；Mock 或语法检查通过不等于真实行为已验证；未执行的明确写“未验证”。
- 回复末尾三行：读取的规范 / 已验证 / 未验证。

## 按需读取

- 涉及身份授权、CSRF、数据归属、日志、规范与项目冲突的处理：[工程底线](references/工程底线.md)
- 新增共享能力、抽取复用、补充注释的细则：[代码复用与注释](references/代码复用与注释.md)
- 文件上传、下载、下载包发布：使用 `file-upload-download`

按技术栈叠加：Java 用 `java-coding`，Spring Boot 用 `springboot-*`，前端用 `typescript-frontend` 与 `vue-*`，数据与中间件用 `mysql-engineering`、`redis-engineering`、`minio-file-lifecycle`、`nginx-proxy`，文件上传下载用 `file-upload-download`，接口契约用 `api-contract`，容器用 `docker-deploy`，目录与部署边界用 `deploy-layout`，公开高成本接口用 `abuse-protection`，安全编码用 `security-baseline`，提交用 `git-delivery`，审查用 `code-review`。
