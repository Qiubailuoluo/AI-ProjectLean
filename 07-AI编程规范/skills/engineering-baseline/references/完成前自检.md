# 完成前自检

适用范围：新增或修改实现代码、配置或脚本后，交付之前。低影响的文字、样式改动只做第 1、5 项。

## 清单

1. **范围**：改动只包含本任务需要的内容；没有顺手重构、格式化无关文件、带入本地调试配置或密钥。
2. **复用**：已检查现有实现，没有新建与现有能力同义的封装、依赖或接口。
3. **失败路径**：失败、超时、重复请求、空结果、权限不足时的行为已明确，没有吞掉异常后报告成功。
4. **权威性**：身份、价格、状态等结论来自后端或可信来源；前端隐藏、请求自报字段不作为授权依据。
5. **验证**：已按风险执行验证，并在交付中分别说明：

   | 类别 | 状态 |
   | --- | --- |
   | 静态检查（类型、lint、编译） | 已执行 / 未执行 |
   | 构建 | 已执行 / 未执行 |
   | 自动化测试 | 已执行 / 未执行，覆盖了什么 |
   | 真实运行（真实数据库、服务、浏览器） | 已执行 / 未执行 |

   Mock 或语法检查通过，不写成"真实行为已验证"。
6. **敏感信息**：日志、提交、说明文字中没有密钥、令牌、密码、带签名的完整 URL。
7. **文档同步**：行为、接口、配置或命令变化时，相关注释与说明已更新或删除失效内容。

## 交付格式

回复末尾用三段短句即可，不复制整份清单：

```text
读取的规范：<实际读取的文件，如 springboot-api/SKILL.md、接口与异常.md>
已验证：<分类写明命令或手段与结果>
未验证：<未执行的检查及原因，或"无">
```

重要条款有偏离时，补一句理由。
