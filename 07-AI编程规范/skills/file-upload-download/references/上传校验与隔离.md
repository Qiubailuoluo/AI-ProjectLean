# 上传校验与隔离

适用：文件上传入口、上传确认、压缩包处理。

## 限制放在哪一层

- 前端预检格式、数量、大小并给出反馈。后端和实际存储入口各自独立再校验。
- 直传绕过后端时，存储写入本身也要限制：签发前校验权限和配额，确认前复核实际对象。
- 确认阶段的校验拦不住"已经占用的存储"。按目标能力核对签名策略、并发配额预留、上传字节上限。做不到硬限制，就改走受控上传路径。
- 超限或未确认的对象不能发布，并且要有回收路径。
- 浏览器自动携带 Cookie 时，上传、确认、发布、删除入口要做 CSRF 防护，见[工程底线](../../engineering-baseline/references/工程底线.md#通用要求)。

## 内容校验

- 校验扩展名、实际格式、大小和必要的内容特征。不只信 `Content-Type`、客户端摘要、文件名。
- 拒绝不支持的格式。加密压缩包等无法检查的内容，明确拒绝或隔离。
- 检测器或处理库故障时，按失败处理，不当作通过。

## 隔离

- 对象标识或路径由服务端生成。按用户或租户、暂存或已发布分开存放。
- 文件放在不可执行的位置，用最小权限。
- 没通过检查的文件，不能被公开路径读取，也不被后台自动处理。
- 上传凭据、完成确认、最终业务引用必须指向同一份已验证的内容，防止校验后被覆盖。对象存储的版本绑定见 `minio-file-lifecycle`。

## 压缩包

- 只存储和下载的压缩包，默认不需要为校验而解压。
- 确需解压、预览、扫描时，限制：解压后字节数、条目数、压缩比、嵌套深度、处理时间。
- 检查规范化路径、绝对路径、`..`、符号链接，防路径穿越和解压炸弹。
- 处理库保持在受支持的版本。使用受限的临时空间，失败后清理产物。按风险复用恶意内容扫描。
