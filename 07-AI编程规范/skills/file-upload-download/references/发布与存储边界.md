# 发布与存储边界

适用：管理员发布下载包、安装包，用户附件的存放和发布状态。按项目已有的文件服务或对象存储实施，不要求迁移。

## 放在哪里

- 与前端版本无关的压缩包、安装包、用户文件，放在前端发布目录之外：受控文件目录或对象存储。
- 不放进前端源码、`public/`、构建产物。
- 可以复用已有文件服务，不必新建进程。
- 界面用的图标、字体，以及明确要求离线交付的资源，可以留在前端。
- 迁移已有资源前，先查调用方和历史链接，不直接删除。

## 怎么记录

- 业务记录保存：稳定资源 ID、归属（用户或租户）、版本、状态、大小、摘要。
- 不把临时签名 URL 当永久地址。
- 公开资源和用户私有附件分别定义可见性。
- 用户原文件名只用于展示。不进存储路径，不当授权凭据。

## 状态与权限

- 管理员上传也要经过认证、发布权限、内容校验、大小校验。
- 状态至少区分：已上传、待校验、已发布、已下架、已删除。名称和审批流程按项目定。
- 发布前核对：存储容量、暂存清理、失败重试、可恢复的备份。
- 替换资源时保留版本和引用关系。新版本上传失败，不能破坏旧版本。
- 需要时记录脱敏的发布、授权、下架、删除审计。

## 下载地址

- 由服务端按资源记录和受控配置解析。
- 不信任客户端传入的磁盘路径、对象 Key、远程地址。
- 读本地磁盘时：规范化路径，确认在受控根目录内，处理符号链接逃逸。不直接拼接用户路径。
- 服务端要拉取远程资源时，限制目标和重定向，防 SSRF。没有需求就不加这个能力。
