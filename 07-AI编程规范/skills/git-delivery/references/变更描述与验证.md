# 变更描述与验证

适用范围：PR/MR、交接说明及较复杂提交正文。优先遵循仓库模板，篇幅按改动复杂度确定；简单变更无需填写无关章节。

- 首句说明具体问题和修改后的行为；标题围绕最终差异，不能沿用已放弃方案或对话中的临时目标。
- 正文解释关键实现及其原因、受影响调用方和必要取舍。纯文件清单不足以说明行为；可从差异直接看出的细节不逐项复述。
- 验证记录说明执行的命令或场景、结果及实际边界，分别列出未运行项和原因。构建、Mock、集成测试及真实环境验证不能相互替代；代码审查结论不等于测试通过。
- 接口、数据结构、配置或部署契约变化时，说明兼容期、迁移/发布顺序及必要回退限制。用户可见的 UI 变化按需要附脱敏截图；不得附带真实令牌、签名地址或私有数据。
- 描述与最终差异及验证结果保持同步；范围变化后重写标题和正文。简洁说明已知限制，避免复述对话过程或未实现的承诺。

可选正文骨架，项目模板优先：

```text
问题与结果：<触发条件、原行为、修改后的行为>
关键变更：<影响判断的实现与取舍>
验证：<已执行及结果；未执行及原因>
兼容与发布：<仅涉及契约、迁移或运行风险时填写>
```
