# 提交隔离与产物边界

适用：提交前排除仅本地的修改、配置 `.gitignore`、检查构建和上传产物。个人配置的写法见[本地运行配置](本地运行配置.md)。

## 忽略规则

- 团队共用的未跟踪本地文件模式，写进项目 `.gitignore`。
- 仅个人需要的排除，用仓库本地的 `.git/info/exclude` 或个人排除规则。不为个人习惯扩大团队规则。
- 忽略规则要验证：实际匹配了哪些文件，这些文件是否已被跟踪。
- `.gitignore` 屏蔽不了已跟踪文件的修改。
- 不要把加入忽略规则、`assume-unchanged`、`skip-worktree`，当作可靠的本地配置管理或提交隔离机制。
- 不要为了隐藏本地差异，直接取消团队必需配置的跟踪。

## 提交前

- 核对工作区和暂存区，逐项排除"仅本地"的修改。
- 按路径或片段暂存。避免批量暂存、强制添加被忽略的文件，避免会收录全部已跟踪修改的提交方式。
- 发现本地配置误入暂存区：只调整相关的暂存内容，保留工作区需要的值，不批量还原用户的修改。

## 构建与发布产物

- Git 忽略不控制构建、镜像、云端同步。
- 生产交付用明确的版本和构建环境。检查：环境文件、资源打包、Docker context、上传清单。避免工作区里的本地覆盖进入发布产物。
- 目录和部署的细节，使用 `deploy-layout`，读「项目目录与文件归属」。

## 交付说明与泄露处置

- 交付时分别说明：已提交的共享变更、保留的本地适配、未验证的环境。
- 秘密已经提交或推送：按项目的泄露处置流程处理，撤销或轮换凭据。只删除当前文件、追加忽略规则，消除不了泄露。

## 验证

核对：忽略规则、已跟踪状态、最终的暂存差异。

参考：[Git 忽略规则](https://git-scm.com/docs/gitignore)、[Git 索引标记限制](https://git-scm.com/docs/git-update-index)。
