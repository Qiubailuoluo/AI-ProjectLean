# 本地运行配置

适用：拉取代码后，为本机启动、调试、测试调整配置、脚本或代码。先区分"个人环境适配"和"应共享的产品修复"。本机能跑，不能证明他人环境或服务器可用。提交和产物的隔离见[提交隔离与产物边界](提交隔离与产物边界.md)。

## 本地适配

- 优先用项目已有的环境变量、外置配置、个人运行参数、开发覆盖机制。
- 不把个人地址、端口、绝对路径、凭据、调试开关，直接写进共享的默认配置。
- 核对配置加载顺序、激活方式、实际目标，避免本地启动连到生产资源。
- Vue/Vite：按实际模式用 `.env.local` 或 `.env.[mode].local`。核实忽略规则，以及构建时是否加载。`.local` 这个名字，不保证隔离。
- Spring Boot：用项目支持的外部配置，或显式激活的本地 Profile。不要因为文件名带 `local`，就推定它不会打进产物。

## 哪些该提交

- 通用默认值、无敏感值的示例、必要的启动说明，按项目约定提交。
- 个人配置和秘密，保持本地或受控注入。
- 不要用笼统的 `.env*` 或配置目录忽略规则，屏蔽团队需要维护的模板和正式配置。

## 临时修改已跟踪文件

- 确需临时改已跟踪的配置或实现代码时，在任务记录或交付说明里列出"仅本地"：相对路径、修改目的、影响范围、恢复方式。不记录真实秘密。
- 与产品修复混在同一个文件时，按片段区分。
- 真正的兼容性修复，要按需求验证后正常提交。不能仅因为是在本地发现的，就永久排除。

## 不要放宽安全

- 不为启动方便，关闭正式的认证、租户校验、TLS 校验，不放宽生产安全策略。
- 需要测试替身或开发专用行为时，隔离生效范围，并验证默认环境不会启用。

## 验证

- 核对：本地启动的真实地址、生效配置。
- 共享配置确有变更时，验证默认或目标模式，以及没有个人覆盖的构建路径。
- 没有部署环境时，不要声称服务器已验证。只有本地启动需求时，不要为了验证擅自连接生产资源。

参考：[Vite 环境模式](https://vite.dev/guide/env-and-mode)、[Spring Boot 外部配置](https://docs.spring.io/spring-boot/reference/features/external-config.html)。框架规则以目标版本为准。
