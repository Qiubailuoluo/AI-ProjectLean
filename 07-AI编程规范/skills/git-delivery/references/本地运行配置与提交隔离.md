# 本地运行配置与提交隔离

适用范围：拉取代码后，为本机启动、调试或测试调整配置、脚本或代码。先区分个人环境适配与应共享的产品修复；本机可运行不证明他人环境或服务器可用。

## 本地适配

- 优先使用项目已有的环境变量、外置配置、个人运行参数或开发覆盖机制，不直接把个人地址、端口、绝对路径、凭据或调试开关写入共享默认配置。核对配置加载顺序、激活方式和实际目标，避免本地启动连接生产资源。
- Vue/Vite 可按实际模式使用 `.env.local` 或 `.env.[mode].local`，但须核实忽略规则和构建时是否加载；`.local` 名称不保证隔离。Spring Boot 使用项目支持的外部配置或显式激活的本地 Profile，不因文件名含 `local` 就推定不会打入产物。
- 通用默认值、无敏感值的示例及必要启动说明可按项目约定提交；个人配置与秘密保持本地或受控注入。不要用笼统的 `.env*` 或配置目录忽略规则屏蔽团队需要维护的模板和正式配置。
- 确需临时修改已跟踪配置或实现代码时，在自己的任务记录或交付说明中列明“仅本地”：相对路径、修改目的、影响范围及恢复方式，不记录真实秘密。与产品修复混在同文件时按片段区分；真正的兼容性修复须按需求验证后正常提交，不能仅因在本地发现就永久排除。
- 不为启动方便关闭正式认证、租户校验、TLS 校验或放宽生产安全策略；如需测试替身或开发专用行为，须隔离生效范围并验证默认环境不会启用。

## Git 与产物边界

- 团队共用的未跟踪本地文件模式写入项目 `.gitignore`；仅个人需要的排除可用仓库本地 `.git/info/exclude` 或个人排除规则，不为个人习惯扩大团队规则。忽略规则应验证实际匹配及文件是否已跟踪。
- `.gitignore` 不屏蔽已跟踪文件的修改。不得把加入忽略规则、`assume-unchanged` 或 `skip-worktree` 当作可靠的本地配置管理及提交隔离机制；不得为隐藏本地差异直接取消团队必需配置的跟踪。
- 提交前核对工作区与暂存区，逐项排除仅本地修改；按路径或片段暂存，避免批量暂存、强制添加忽略文件，或使用会收录全部已跟踪修改的提交方式。发现本地配置误入暂存区时，只调整相关暂存内容并保留工作区所需值，不批量还原用户修改。
- Git 忽略不控制构建、镜像和云端同步。生产交付使用明确的版本与构建环境，检查环境文件、资源打包、Docker context 和上传清单，避免工作区中的本地覆盖进入发布产物；细节见[项目目录与部署边界](../../engineering-baseline/references/项目目录与部署边界.md)。
- 交付分别说明已提交的共享变更、保留的本地适配及未验证环境。秘密已经提交或推送时按项目泄露处置流程处理并撤销/轮换凭据，单纯删除当前文件或追加忽略规则不能消除泄露。

## 验证

核对本地启动的真实地址及生效配置、忽略规则、已跟踪状态和最终暂存差异。共享配置确有变更时，验证默认/目标模式及无个人覆盖的构建路径；未具备部署环境时不能声称服务器已验证。只有本地启动需求时，不为验证而擅自连接生产资源。

参考：[Git 忽略规则](https://git-scm.com/docs/gitignore)、[Git 索引标记限制](https://git-scm.com/docs/git-update-index)、[Vite 环境模式](https://vite.dev/guide/env-and-mode)、[Spring Boot 外部配置](https://docs.spring.io/spring-boot/reference/features/external-config.html)。框架规则以目标版本为准。
