# MinIO 文件生命周期

先确认 MinIO 或 S3 兼容服务的发行版和版本、SDK、bucket 策略、对象版本、访问方式。

## 核心规则

- 上传凭据（预签名）短时效，并限定对象 Key、方法、大小和类型。
- 流程：上传到临时位置 → 服务端确认（大小、类型、摘要）→ 与业务记录绑定；未绑定的对象要定期清理。
- 私有对象在授权校验通过后签发短期访问地址；日志不记录完整的签名 URL。
- 数据库事务不覆盖对象存储；替换和删除要处理部分失败，清理可重试且幂等。
- 对象 Key 由服务端生成，不使用用户提交的文件名作路径。
- bucket 不开放公开写；公开读仅限明确的公开资源。

## 按需读取

- 对象身份、上传确认、业务绑定：[对象身份与上传确认](references/对象身份与上传确认.md)
- 私有对象的读取、预签名下载：[下载与访问控制](references/下载与访问控制.md)
- 替换、删除、版本、生命周期、备份与对账：[替换删除与恢复](references/替换删除与恢复.md)
- 下载包发布、文件校验、隔离、配额：同时使用 `file-upload-download`
- 签发滥用、异常频率：读 `abuse-protection`「限流与入口约束」
- 经 Nginx 转发上传或缓存下载：同时使用 `nginx-proxy`
- 用户或租户数据归属、敏感信息：读 `engineering-baseline`「工程底线」

## 验证

上传与数据库绑定之间的部分失败、重复确认、越权访问、替换失败、清理重试。数据库事务不覆盖对象存储。
