# 对象身份与上传确认

适用：MinIO 或 S3 兼容存储的上传、确认、业务绑定。能力以目标发行版、版本、SDK、bucket 策略为准，实施前先核对。

## 对象身份

- 对象引用 = 存储域 + bucket + object key，启用版本控制时再加 version ID。端点从受控配置解析。
- 预签名 URL 是有期限的访问凭据，不是对象标识。
- object key 由服务端按项目规则生成，并关联用户或租户的授权范围。客户端文件名只当展示数据。
- 数据库存业务记录和对象引用，不存对象内容。常见字段：bucket 与 key、version ID、归属、生命周期状态、大小、摘要、检测出的媒体类型、时间。
- 绑定前核对：调用者、对象归属、用途、上传意图、当前状态。对象存在，不等于有权绑定。

## 上传与确认流程

1. **创建上传意图**：服务端确定授权范围，生成不可预测或防冲突的临时 key，记录允许的大小、用途、类型、有效期。
2. **签发凭据**（直传时）：预签名凭据只限目标对象、操作方法、必要请求头，有效期要短。
   - 注意：预签名 PUT 在到期前可以重复覆盖同一对象。唯一的临时 key 只隔离不同的上传，不阻止同一凭据再次覆盖。
3. **核实上传结果**：用可信手段（如查询对象元数据）核实 key、实际大小、可得的校验信息。不信客户端的成功响应和 `Content-Type`。
4. **校验内容**：按风险校验实际格式、恶意内容、配额、业务约束。多段上传或加密会改变 `ETag` 的含义，不要把 `ETag` 一律当整个文件的 MD5。
5. **固定内容**：被校验的内容，必须与最终业务引用是同一份，且不能被上传凭据替换。做法二选一：
   - 用已验证的固定 version ID；
   - 复制到客户端无写权限的最终 key。复制源要固定版本或带条件保护；固定不了，就先生成最终对象，再验证它。
   之后一直用同一个对象身份读取。
6. **绑定业务**：按项目的事务边界建立引用。暂存、确认、绑定状态要能恢复；重复确认要幂等；数据库失败时，保留清理或重新绑定的路径。

## 后端代理上传

- 用有界的流式处理。关闭输入流和对象响应。限制并发、大小、处理时间。
- 大文件直传要配置"未完成 multipart upload"的回收策略。
- 经 Nginx 转发时，一并检查请求体、缓冲、超时，见 `nginx-proxy`。

## 验证

覆盖：上传超限、内容不符、重复确认、确认后被覆盖、数据库写入失败。记录目标服务与 SDK 版本、实际校验方式。

参考：[MinIO Java SDK API](https://github.com/minio/minio-java/blob/master/docs/API.md)；[S3 预签名 URL 的重复使用与覆盖语义](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。功能是否适用于目标部署，以其版本和发行版文档为准。
