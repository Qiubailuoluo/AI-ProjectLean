# 替换、删除与恢复

适用：文件替换、删除、对象版本、生命周期规则、备份与对账。

## 替换

- 新内容使用独立的对象身份。
- 新对象验证并绑定成功后，再按引用关系处理旧对象。
- 数据库更新和对象操作不在同一个事务里，流程要能从部分失败中恢复。

## 删除

- 分三步考虑：业务解绑、逻辑状态变更、对象物理删除。
- 判定时考虑共享对象、并发引用、重试。
- 删除任务可以安全重放，并记录最终结果。

## 版本与生命周期

- 版本控制、生命周期规则、对象锁，可能产生删除标记、保留旧版本，或拒绝物理删除。
- 启用版本控制时，明确两件事：
  - 业务记录绑定"最新版本"，还是"固定 version ID"；
  - 旧版本和删除标记何时清理。

## 备份与对账

- 版本控制不是独立备份。恢复方案要覆盖：对象内容、数据库引用、版本信息、凭据与密钥、生命周期配置。并在隔离环境演练。
- 定期核对：未绑定的对象、过期的上传意图、失败的删除、未完成的 multipart upload。
- 自动清理规则不能删除仍可能完成绑定的对象。

## 验证

覆盖：对象替换的部分失败、版本删除、清理重试。

参考：[MinIO AIStor 对象版本](https://docs.min.io/aistor/administration/objects-and-versioning/versioning/)；[对象生命周期](https://docs.min.io/aistor/administration/object-lifecycle-management/)。功能是否适用，以目标部署的版本和发行版文档为准。
