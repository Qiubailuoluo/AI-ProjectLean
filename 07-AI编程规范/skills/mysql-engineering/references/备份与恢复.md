# MySQL 备份与恢复

适用：备份策略、恢复演练、误操作处置、灾难恢复。先定义恢复目标和目标环境。备份作业显示成功，不能证明数据可恢复。

## 策略

- 明确：RPO、RTO、保留周期、可接受的数据损失、恢复范围、责任人。据此选择托管备份、逻辑或物理全量、增量、二进制日志时间点恢复的组合。
- 明确恢复需要哪些内容：表结构、数据、触发器、例程、事件、账号权限、加密材料、配置、日志位置。
- 核实备份工具实际覆盖的范围，以及它与 MySQL 版本、存储引擎的兼容性。
- 备份介质与生产放在不同的故障域。传输和存储按敏感级别加密，限制读取权限，审计访问。
- 保留策略要兼顾：恢复窗口、合规要求、容量、二进制日志的连续性。
- 二进制日志、复制、只读副本，不能替代独立备份。误删和错误写入会传播到副本。
- 备份的一致性、锁影响、对业务负载的影响，取决于工具、引擎、事务、拓扑。评估：备份时的写入影响、复制延迟、恢复所需的日志链。

## 恢复演练

- 定期在隔离环境做：全量恢复、目标时点恢复。
- 验证：表结构、关键数据量、业务不变量、账号权限、应用读写、恢复耗时。
- 记录：备份标识、时间范围、日志位置、目标恢复点、校验结果、耗时、缺陷。演练失败后，修订流程并重新验证。
- 检查保留清理，不会删除仍用于恢复或复制的日志。归档、加密密钥、解密权限，要与备份一起纳入恢复方案。

## 生产恢复

恢复可能覆盖数据，或改变复制拓扑。操作前核实：目标实例、恢复点、期间写入的处置、切换方案。遵循既定的变更流程。
