# MySQL 备份与恢复

适用范围：备份策略、恢复演练、误操作处置或灾难恢复能力变更。应定义恢复目标与目标环境；备份作业成功状态不足以证明数据可恢复。

## 策略

- 明确 RPO、RTO、保留周期、可接受的数据损失、恢复范围和责任人；据此选择托管备份、逻辑/物理全量、增量及二进制日志时间点恢复的组合。
- 明确恢复所需的表结构、数据、触发器/例程/事件、账号权限、加密材料、配置和日志位置；核实备份工具实际覆盖范围及其与 MySQL 版本、存储引擎的兼容性。
- 备份介质与生产故障域隔离，传输和存储按敏感级别加密，限制读取权限并审计访问。保留策略兼顾恢复窗口、合规要求、容量和二进制日志连续性。
- 二进制日志、复制和只读副本不构成独立备份的替代方案；误删或错误写入可能传播至副本。
- 备份一致性、锁影响和业务负载取决于工具、引擎、事务及拓扑；评估备份时的写入影响、复制延迟和恢复所需日志链。

## 恢复演练

- 定期在隔离环境执行全量恢复和目标时点恢复；验证表结构、关键数据量与业务不变量、账号权限、应用读写及恢复耗时。
- 记录备份标识、时间范围、日志位置、目标恢复点、校验结果、耗时和缺陷。演练失败后修订流程并重新验证。
- 检查保留清理不会删除仍用于恢复或复制的日志；归档、加密密钥和解密权限必须与备份一同纳入恢复方案。
- 生产恢复可能覆盖数据或改变复制拓扑状态。操作前核实目标实例、恢复点、期间写入处置和切换方案，并遵循既定变更流程。
