# MySQL 安全与访问控制

适用：数据库账号、权限、连接、敏感数据、日志或安全配置变更。按托管服务、网络拓扑及合规要求确认可用能力。

## 账号与权限

- 应用运行、只读报表、迁移和管理使用职责分离的账号或角色。运行账号仅授予所需 schema、表及操作权限，不授予 `root` 或全局管理权限。
- 权限授予范围尽量具体；核对账号的来源主机、继承角色、默认角色和间接授权。定期回收离岗、废弃或临时账号。
- DDL 权限仅授予受控迁移身份；应用凭据不得拥有用户管理、权限管理或无关管理操作权限。

## 连接与数据

- 网络访问范围限于必要的应用、管理与备份来源。跨不可信网络时按部署要求配置 TLS 并验证服务端身份；仅加密但不校验证书不足以验证连接端点。
- 密码、证书和密钥通过项目受控密钥渠道注入；仓库、镜像、命令历史、SQL 参数日志和工单中不留明文。按轮换策略更换凭据并验证连接恢复。
- SQL 值使用参数绑定；表名、列名和排序方向等不可绑定位置通过固定映射或严格白名单选择。数据库权限不替代应用层租户与资源授权。
- 依据数据敏感级别限制查询、导出、审计和备份访问；清理日志与测试数据中的个人信息和凭据。

## 验证

验证生效授权，而非仅审查配置文件；使用运行账号检查允许与拒绝路径。核对连接加密及证书验证、凭据注入、网络边界和审计记录。生产权限验证不得执行破坏性试探操作。

官方参考：[安全指南](https://dev.mysql.com/doc/refman/en/security.html)、[访问控制](https://dev.mysql.com/doc/refman/en/access-control.html)、[加密连接](https://dev.mysql.com/doc/refman/en/using-encrypted-connections.html)。
