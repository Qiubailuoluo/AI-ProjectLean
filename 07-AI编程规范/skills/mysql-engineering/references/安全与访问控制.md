# MySQL 安全与访问控制

适用：数据库账号、权限、连接、敏感数据、日志、安全配置。按托管服务、网络拓扑、合规要求，确认可用的能力。

## 账号与权限

- 应用运行、只读报表、迁移、管理，分别使用职责分离的账号或角色。
- 运行账号只授予所需 schema、表、操作的权限。不授予 `root` 或全局管理权限。
- 授权范围尽量具体。核对账号的来源主机、继承角色、默认角色、间接授权。
- 定期回收离岗、废弃、临时的账号。
- DDL 权限只给受控的迁移身份。应用凭据不能有用户管理、权限管理、无关管理操作的权限。

## 连接

- 网络访问限于必要的应用、管理、备份来源。
- 跨不可信网络时，按部署要求配置 TLS，并验证服务端身份。只加密、不校验证书，不能证明连接的是正确端点。

## 凭据与数据

- 密码、证书、密钥通过项目受控的密钥渠道注入。仓库、镜像、命令历史、SQL 参数日志、工单里不留明文。按轮换策略更换凭据，并验证连接恢复。
- SQL 值用参数绑定。表名、列名、排序方向等不能绑定的位置，用固定映射或严格白名单。
- 数据库权限不能替代应用层的租户和资源授权。
- 按数据敏感级别，限制查询、导出、审计、备份的访问。清理日志和测试数据里的个人信息和凭据。

## 验证

- 验证生效的授权，不要只审查配置文件。用运行账号检查"允许"和"拒绝"两条路径。
- 核对：连接加密与证书验证、凭据注入、网络边界、审计记录。
- 生产环境验证权限时，不做破坏性试探。
