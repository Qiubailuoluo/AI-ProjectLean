# MySQL 数据建模与约束

适用：新表设计、字段与约束变更、关系建模、历史数据语义调整。依据目标 MySQL 版本、存储引擎、字符集、排序规则、SQL mode。

## 建模

- 从业务不变量、读写路径、数据规模、增长率、保留期、数据归属出发。默认保持关系清晰。
- 反规范化、分区、JSON 字段，要有查询、写入或演进需求支撑。
- 交易、审计等历史事实，按业务要求保存必要的快照。当前的关联记录，还原不出历史时点的名称、价格、状态。
- 只为有依据的业务需求创建字段和表。

## 字段

- 类型要覆盖允许的范围，并控制存储成本。
- 金额：用精确数值，定义精度、舍入、币种。
- 时间：定义时区和精度。
- 字符串：明确长度、字符集、排序规则。
- 字段语义不能依赖隐式类型转换或环境默认值。

## 约束

- 必填、范围、唯一性、引用完整性，先评估能否用数据库约束。
- 唯一键要符合业务作用域和 NULL 语义。应用层"先查再写"，保证不了并发下的唯一。
- 外键、检查约束、唯一约束，按业务完整性、删除生命周期、版本能力选择。不用数据库约束时，要说明由哪个事务、任务或审计流程保证完整性。

## 主键

- 明确主键的生成方式、稳定性、宽度。InnoDB 二级索引带着主键值，主键宽会撑大二级索引。
- 不强制自增或 UUID。按分布式生成、排序、索引局部性的要求选择。

## 删除与保留

删除、软删除、归档、保留期限，要说明对这些方面的影响：唯一键、查询条件、恢复、隐私要求。

## 验证

- 验证：DDL 在目标版本上的语法、字段边界、NULL 与默认值、约束冲突、字符集与排序规则、既有数据的兼容性。
- 记录数据迁移、回填、失败恢复的方式。
- 建表成功，不能证明模型正确。
