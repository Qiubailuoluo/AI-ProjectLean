# MySQL 服务端版本管理

适用：MySQL 补丁更新、主版本升级、降级评估、发行渠道或运行平台变更。实际支持路径随发行系列、平台、拓扑和服务商而异。

## 升级前

- 记录当前和目标精确版本、发行系列、安装来源、操作系统/托管服务、拓扑、存储引擎、插件及客户端驱动版本。
- 审核目标版本发布说明、支持平台、行为变更、弃用/移除项及官方支持的升级路径；运行目标版本兼容性检查工具并处理阻断项。
- 核对应用驱动、认证、字符集、SQL mode、DDL、存储格式、复制和备份工具兼容性。升级可能改变执行计划、资源占用或安全默认值。
- 升级前完成并验证可用备份，确认日志链和恢复方式。降级路径并非普遍受支持；应按目标版本说明评估，更换旧二进制文件不构成充分的回滚方案。

## 演练与发布

- 在隔离副本使用接近生产的数据、配置和拓扑演练完整升级；运行应用集成、迁移、关键查询计划和代表性工作负载对比。
- 记录升级耗时、资源、错误日志、复制延迟和性能差异；定义停止条件、流量切换、恢复点、责任人和用户影响。
- 集群或复制拓扑按官方滚动升级顺序逐节点执行并验证角色状态；单机升级步骤不适用于未经评估的集群拓扑。
- 升级后确认服务端版本、账号/认证、备份、复制、关键业务 SQL 和告警；文档与环境清单记录实际版本。

官方参考：[升级路径](https://dev.mysql.com/doc/refman/en/upgrade-paths.html)、[升级最佳实践](https://dev.mysql.com/doc/refman/en/upgrade-best-practices.html)。
