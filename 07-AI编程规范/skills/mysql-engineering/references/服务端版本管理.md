# MySQL 服务端版本管理

适用：MySQL 补丁更新、主版本升级、降级评估、发行渠道或运行平台变更。支持的升级路径随发行系列、平台、拓扑、服务商而不同。

## 升级前

- 记录当前和目标的精确版本、发行系列、安装来源、操作系统或托管服务、拓扑、存储引擎、插件、客户端驱动版本。
- 审核目标版本的发布说明：支持平台、行为变更、弃用与移除项、官方支持的升级路径。运行目标版本的兼容性检查工具，处理阻断项。
- 核对兼容性：应用驱动、认证、字符集、SQL mode、DDL、存储格式、复制、备份工具。升级可能改变执行计划、资源占用、安全默认值。
- 升级前完成并验证可用的备份，确认日志链和恢复方式。
- 降级路径并不普遍受支持，按目标版本说明评估。换回旧二进制文件，不是充分的回滚方案。

## 演练

- 在隔离副本上，用接近生产的数据、配置、拓扑，演练完整的升级。
- 运行：应用集成、迁移、关键查询计划、有代表性的工作负载对比。
- 记录：升级耗时、资源、错误日志、复制延迟、性能差异。

## 发布

- 定义：停止条件、流量切换、恢复点、责任人、用户影响。
- 集群或复制拓扑，按官方的滚动升级顺序逐节点执行，并验证角色状态。单机的升级步骤，不适用于没评估过的集群。
- 升级后确认：服务端版本、账号与认证、备份、复制、关键业务 SQL、告警。在文档和环境清单里记录实际版本。

官方参考：[升级路径](https://dev.mysql.com/doc/refman/en/upgrade-paths.html)、[升级最佳实践](https://dev.mysql.com/doc/refman/en/upgrade-best-practices.html)。
