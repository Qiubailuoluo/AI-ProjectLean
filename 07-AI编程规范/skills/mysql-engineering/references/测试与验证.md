# MySQL 测试与验证

适用：新增或修改 SQL、约束、迁移、事务行为、并发逻辑，以及查询性能的验证。锁失败和重试见[锁失败与重试](锁失败与重试.md)。

## 测试边界

- 单元测试验证应用分支和参数组装。真实的 MySQL 集成测试，验证 SQL、类型转换、约束、隔离级别、锁、事务、迁移。Mock 或 H2，不能证明这些数据库行为。
- 测试实例要匹配目标的 MySQL 版本、引擎、字符集和排序规则、SQL mode、时区、关键配置。
- 用容器或共享测试库时，核实实际连接地址和隔离策略。

## 数据与清理

- 数据准备用独立 schema、事务或唯一的测试标识。
- 清理只作用于测试资源。测试失败、超时、并发时，也要验证清理和重跑是安全的。

## 并发

- 用独立连接和事务，并控制交错点。
- 所有事务结束后，核对最终数据、约束、副作用。只断言异常或返回码，不足以证明并发结果。

## 迁移

- 覆盖：空库初始化、从受支持的旧版本升级、有代表性的既有数据、重复部署与失败恢复、新旧应用兼容。
- 破坏性变更，在隔离副本和有代表性的数据上评估。

## 性能

- 用有代表性的数据量、分布、参数、并发，固定环境和采样方式。
- 对照：正确性、延迟、吞吐、扫描量、资源、写入成本。

## 验证记录

分别记录：SQL 静态审查、构建、单元、集成、迁移、并发、性能。注明：实际运行的命令、MySQL 版本和引擎、数据规模、关键结果、未覆盖的范围。测试通过，不等于对生产负载的保证。
