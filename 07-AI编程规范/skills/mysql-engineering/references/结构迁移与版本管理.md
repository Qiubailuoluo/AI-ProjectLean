# MySQL 结构迁移与版本管理

适用：DDL 进入版本库、部署顺序、兼容性、生产表结构变更。沿用项目已采用的迁移工具和发布流程，不引入第二套 schema 管理来源。

## 迁移记录

- 把结构变更作为可审查、可排序、可重复部署的版本化迁移，并与应用代码关联。
- 记录：影响对象、数据回填、预估的锁和耗时、验证方式、失败处置、恢复方案。
- 已在共享环境应用的迁移，视为不可变。要修正，写后续迁移。
- 工具的重复执行语义、校验和、基线、失败恢复，按其实际配置确认。
- 检查目标版本的：DDL 原子性、隐式提交、在线算法、元数据锁、复制影响。不要假设整个迁移能被普通事务回滚，或能在线执行。
- 大表变更前，评估：重建时间、锁、临时磁盘、复制延迟、业务负载。按项目工具选择在线变更或分批回填，并定义中止阈值。

## 发布兼容

- 滚动发布或回退方案采用"扩展、收缩"两阶段：先加兼容结构，部署兼容代码，分批回填并核对，再切换读写。确认旧版本不再依赖后，才移除旧结构。
- 破坏性变更和应用发布分阶段进行。旧代码还在运行时，保留它依赖的字段和约束。
- 新增 `NOT NULL`、唯一约束、类型收窄、重命名之前，先处理既有数据。
- 数据库结构回退和应用版本回退，是不同的操作。制定前向修复方案。要用备份恢复时，见[备份与恢复](备份与恢复.md)，并评估期间的写入。
- CI/CD 校验：迁移顺序、目标版本、应用兼容性。紧急手工变更，要回写迁移历史，保持唯一可追溯的状态。

## 验证

- 在有代表性的旧结构和数据副本上演练：应用顺序、耗时、锁、失败恢复、新旧代码并行。
- 生产发布前确认：备份、监控指标、维护窗口、停止条件、负责人。

官方参考：[InnoDB 在线 DDL](https://dev.mysql.com/doc/refman/en/innodb-online-ddl.html)、[原子 DDL](https://dev.mysql.com/doc/refman/en/atomic-ddl.html)。工具的行为，以项目选用的迁移工具版本文档为准。
