# Nginx 代理缓存

适用：用 `proxy_cache` 缓存上游的 HTTP 响应。规则依据目标 Nginx 版本、发行版、构建模块、响应契约。

## 缓存边界与 Key

- 只缓存"响应契约明确、允许跨请求复用"的资源。认证结果、租户数据、个性化响应，不能在共享缓存里串用。
- Cache Key 要覆盖所有影响响应内容的维度：协议、主机、路径、查询参数，以及适用时的租户、语言、内容协商条件。Key 少一个维度，就可能错误复用。
- 认证或 Cookie 会影响响应时：默认绕过读取，并禁止写入。要按用户分区缓存的话，先评估权限撤销、身份轮换、Key 基数、容量风险。
- 请求头 `Authorization`、`Cookie`，响应头 `Set-Cookie`、`Vary`、`Cache-Control`，其处理要与代理缓存策略一致。源站缓存头和 Nginx 配置谁优先，按目标版本核验。

## 私有预签名 URL

- MinIO/S3 私有预签名 URL 的身份凭据，可能在查询串里。
- 缓存命中不访问源站，可能绕过源站对签名到期的校验。Key 里保留完整签名参数，也解决不了这个问题。
- 默认：对这类请求同时绕过读取、禁止写入。
- 确实要缓存私有内容时：每次请求在命中缓存之前，都要完成有效的验签或授权，并用受控的对象身份和版本定位内容。
- 不要删掉签名参数来合并 Key，再共享响应。

## 读取、写入、有效期

- `proxy_cache_bypass` 控制是否绕过缓存读取。`proxy_no_cache` 控制响应是否写入缓存。涉及个性化或授权数据时，两类条件都要定义。只绕过读取，响应仍可能被写进共享缓存。
- 按响应类型设置缓存的状态码和 TTL。明确：过期数据的可用范围、源站不可用时是否给 stale 响应、热点回源合并、响应头更新。
- 缓存目录、`keys_zone`、`max_size`、非活跃清理、临时磁盘、inode 用量，都纳入容量监控。缓存失效或更新，按实际的 Key 和配置规则执行。
- `proxy_cache_purge` 等清除能力，随版本、发行版、模块而不同。实施前确认目标构建是否支持，以及该指令的授权条件。

## 验证

- 覆盖：匿名与认证请求、不同租户和语言、查询参数变化、源站更新、TTL 到期、绕过与禁止写入的路径。
- 私有链接额外验证：缓存 HIT 时，无签名、篡改、过期、授权撤销的行为。
- 检查：缓存状态、Key 隔离、响应体、响应头。确认没有跨身份复用，源站故障时行为符合预期。
