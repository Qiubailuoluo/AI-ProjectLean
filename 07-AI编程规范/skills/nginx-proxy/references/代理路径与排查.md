# Nginx 代理路径与请求排查

适用：反向代理、路径映射、配置发布、上游故障定位。指令的行为以目标 Nginx 版本、构建模块、生效配置为准。

## 路径匹配与 URI 映射

- 核对：虚拟主机选择、`location` 匹配、`rewrite`、`proxy_pass`、应用上下文、上游路由。
- Nginx 的 `location` 用规范化 URI 匹配。精确匹配、最长前缀、正则匹配的顺序，会影响最终命中的配置块。
- 普通前缀 `location`，且没有 `rewrite` 或变量改写时：`proxy_pass` 带 URI，就用该 URI 替换匹配的前缀；不带 URI，通常把原请求 URI 传给上游。其他配置形态，按目标版本文档和实际配置判断。

| 配置 | 上游收到的 URI |
| --- | --- |
| `location /api/ { proxy_pass http://app/; }` | `/api/orders` 映射为 `/orders` |
| `location /api/ { proxy_pass http://app; }` | `/api/orders` 保留为 `/api/orders` |

## 日志

- 日志要能区分：客户端路径、规范化路径、命中的配置、上游状态与耗时。
- `$request_uri` 含查询串。涉及预签名 URL、令牌、敏感参数时，记录脱敏的路径和请求 ID，不记录完整 URI。
- 代理到 MinIO 或其他签名 URL 服务时：上游 Host、规范化路径、查询串，要与签名请求一致。改写 Host 或 URI 会导致验签失败。同时使用 `minio-file-lifecycle`。

## 配置发布

- 检查所有 `include` 文件和实际生效的配置。
- `nginx -t` 只检查语法和引用，不能证明上游、授权、业务行为正确。
- 导出完整配置前，移除凭据和内部地址。
- 重载前，在目标环境做语法检查。重载后，确认工作进程、监听端口、上游状态，并验证有代表性的请求。
- 按项目流程，保留可恢复的上一版配置。

## 故障定位

- 用"应用直连"和"外部入口"对照，定位 404、401/403、413、502/504。
- 结合：命中的 `location`、上游状态、耗时、请求 ID、应用日志，区分代理、认证、应用、依赖各自的故障。
