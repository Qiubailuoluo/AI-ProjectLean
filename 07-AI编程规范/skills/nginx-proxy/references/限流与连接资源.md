# Nginx 限流与连接资源

适用：请求速率、突发流量、并发占用、慢请求的资源限制。先核对实际入口、目标版本、生效配置。

## 限流配置

- 按真实流量路径，配置：`limit_req` 的频率、突发量、延迟行为，`limit_conn` 的并发边界。
- 限流键要有效且来源可信。空键可能不计数。
- 核对配置的作用域、继承、所有可达的入口。不复制脱离业务预算的固定阈值。

## 客户端地址

- CDN 或负载均衡之后的客户端地址，只从明确可信的代理解析。没配置好时，整个代理出口会被当成一个客户端。
- IP 限制不能代替应用层的账号和租户预算。源站直连的入口也要有约束。

## 拒绝状态

- `limit_req` 和 `limit_conn` 默认拒绝状态是 503。对外约定 429 时，显式设置状态指令，并核对错误页和应用响应。
- HTTP/2、HTTP/3 下，`limit_conn` 对并发请求分别计数，不等于底层 TCP 连接总数。

## 慢请求与多节点

- 慢请求还要核对：请求头和请求体的读取超时、缓冲、临时磁盘。长连接和大文件，另定预算。
- 单实例 Nginx 的共享区，不会自动覆盖多个独立节点。边缘限流和应用的全局配额，按实际部署协调。

## 验证

- 先在受控环境核验规则。版本支持时，用 dry-run 观察误伤，再按发布流程启用。
- 验证：合法突发、超限、可信代理解析、并发占用、恢复。观察上游实际收到的请求量。

业务预算、人机验证、全局计数：使用 `abuse-protection`，读「限流与入口约束」。需要调整转发头、超时、发布配置时，再读[代理路径与排查](代理路径与排查.md)。
