# Nginx 限流与连接资源

适用范围：请求速率、突发流量、并发占用及慢请求资源限制。先核对实际入口、目标版本和生效配置；不因修改 URI 映射自动加载本文件。

- 按真实流量路径配置 `limit_req` 的频率、突发量和延迟行为，以及 `limit_conn` 的并发边界。限流键应有效且来源可信，空键可能不计数；配置作用域、继承及所有可达入口均须核对。不复制脱离业务预算的固定阈值。
- CDN/负载均衡后的客户端地址，仅从明确可信的代理解析；未正确配置时可能把整个代理出口视为一个客户端。IP 限制不能替代应用层账号/租户预算；源站直连入口须有相应约束。
- `limit_req` 和 `limit_conn` 默认拒绝状态为 503；对外约定为 429 时显式设置相应状态指令，并核对错误页及应用响应。HTTP/2、HTTP/3 下 `limit_conn` 将并发请求分别计数，不能等同于底层 TCP 连接总数限制。
- 慢请求还需核对请求头/体读取超时、缓冲和临时磁盘，长连接与大文件另定预算。单实例 Nginx 共享区不自动覆盖多个独立节点；边缘限流与应用全局配额按实际部署协调。
- 先在受控环境核验规则，版本支持时可用 dry-run 观察误伤，再按发布流程启用。验证合法突发、超限、可信代理解析、并发占用及恢复，并观察上游实际请求量。

参考：[请求限流模块](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)、[连接限制模块](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html)、[可信地址解析](https://nginx.org/en/docs/http/ngx_http_realip_module.html)。
