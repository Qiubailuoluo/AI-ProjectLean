# Redis 工程规范

先确认 Redis 的职责、客户端和服务端版本、权威数据源、允许的陈旧范围、故障策略。

## 核心规则

- 先明确 Redis 的角色：可重建缓存，还是权威数据。本规范默认缓存可丢失、可重建。
- Key 有统一前缀和版本；缓存数据设置 TTL（加随机抖动防同时过期）；避免大 Key 和无界集合。
- 写路径：以数据库事务提交为成功边界，提交后再失效缓存；删除失败要有重试或有限 TTL 兜底，提交后回调本身不保证投递；防止旧值回填的竞态。
- 防穿透和击穿：空值短 TTL 缓存；热点 Key 重建加互斥或合并请求。
- 缓存故障时降级回源并保护数据库，不让缓存异常直接变成业务失败（以项目降级策略为准）。
- 客户端配置连接和命令超时、连接池上限；生产环境不用 `KEYS`，用 `SCAN`。
- Key 中不含敏感信息；不同租户或用户的数据要用 Key 隔离。
