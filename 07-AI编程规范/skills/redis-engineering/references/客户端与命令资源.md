# 缓存客户端与命令资源

适用：可重建缓存的客户端、连接预算、批处理、扫描清理、安全连接。以实际的客户端版本和连接模型为准。

## 连接

- 复用项目已有的客户端生命周期。核对连接建立、命令执行、连接池等待、重连的预算。
- 请求结束时不要关闭应用共享的客户端。
- 流水线、事务、订阅、阻塞命令是否需要专用连接，按实际客户端的规则判断。不要把缓存的连接模型直接套到其他用途。

## 命令

- 批量操作限制命令数和返回字节数。
- Pipeline 减少往返，但不自动提供原子性。
- Lua、函数、大集合操作要有执行成本的上限，避免长时间阻塞其他请求。
- `SCAN` 不是一致性快照：遍历可能重复，也会受并发变化影响。清理任务要幂等，并限定在命名空间内。

## 失败处理

- 连接失败、命令超时、写入结果未知，分别处理。
- 重连和重试要有次数上限，并避免同时重试造成风暴。

## 安全

- 核对访问网络、ACL 和凭据。跨非可信网络要有传输保护。
- 缓存服务不能无认证地暴露在公网。

## 验证

按改动覆盖：连接复用、超时与断线重连、批次与返回量上限、扫描重复处理、清理范围。凭据或网络策略变化时，验证拒绝路径。缓存失效或回源策略本身变化时，再读[缓存读写与一致性](缓存读写与一致性.md)。

参考：[Redis Pipeline](https://redis.io/docs/latest/develop/using-commands/pipelining/)、[SCAN 遍历保证](https://redis.io/docs/latest/commands/scan/)。
