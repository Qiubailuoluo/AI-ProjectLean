# 安全编码底线

补充 `engineering-baseline` 中的身份授权与敏感信息要求，聚焦具体漏洞类型。默认拒绝：未明确授权的访问一律拒绝。

## 核心规则

**注入与输出**
- SQL 一律参数绑定；执行系统命令不拼接用户输入，用参数数组而非 shell 字符串。
- 防 XSS：输出转义；Vue 中避免 `v-html`；富文本用白名单净化；按项目情况配置 CSP。
- 用户提供的 URL 渲染到 `href`/`src` 前，只允许 `http`、`https` 等白名单协议，拦截 `javascript:`；后端保存前就清洗。
- 外部输入进日志要限长并处理换行，防日志伪造。

**路径、URL 与反序列化**
- 用户提供的文件名或路径须规范化并确认仍在允许目录内（防路径穿越）；落盘文件名由服务端生成。
- 服务端按用户提供的 URL 发请求（SSRF）：优先用协议、域名、IP 白名单；禁用 HTTP 客户端自动跟随重定向（或对每一跳重新校验）。
- 白名单做不到时才用黑名单：拦截内网、回环、链路本地（含 `169.254.169.254` 云元数据）及 IPv6 对应段。黑名单容易被绕过。
- 域名要解析后校验 IP，并只连接已校验的地址，防 DNS rebinding。
- 不反序列化不可信数据到任意类型；禁用 Java 原生序列化处理外部输入；JSON 只绑定到明确的 DTO。

**密码与令牌**
- 密码哈希首选 Argon2id；不可用时用 scrypt；bcrypt 仅用于老系统（成本因子不低于 10，输入限 72 字节）；要求 FIPS 时用 PBKDF2-HMAC-SHA256。参数按 OWASP 最低配置并在目标机器上实测。
- 不用 MD5、SHA 单次哈希存密码；盐由库自动生成；比较用常量时间。
- 令牌（JWT、会话）：设置过期；校验签名并由服务端固定允许的算法，不信任令牌头里的 `alg`，默认拒绝 `none`；校验 `iss`、`aud`、`exp`；HS256 的密钥要有足够熵，不用人记得住的口令；不放 URL；明确退出和改密后的失效策略。
- 会话 Cookie 设 `HttpOnly`、`Secure`、`SameSite`。跨站携带需要 `SameSite=None` 且必须同时 `Secure`，此时要另做 CSRF 防护。
- 安全场景的随机数用 `SecureRandom` 等密码学随机源，不用 `Random`、`Math.random`。

**跨域与上传**
- CORS 来源用白名单。带凭据的请求，`Access-Control-Allow-Origin`、`Allow-Headers` 都不能是 `*`，要写明确的值；不要原样回显请求的 `Origin`。CORS 不能替代 CSRF 防护。
- 上传校验大小、内容类型（看内容而非扩展名），限制频率；上传目录不可直接执行。
- 登录、验证码、短信等接口必须有频率限制和锁定策略，见 `abuse-protection`。

**依赖与错误**
- 引入依赖前核对来源、维护状态和已知漏洞；锁定版本；使用项目已有的扫描工具（如 `npm audit`、依赖检查插件）。
- 对外错误信息不暴露堆栈、SQL、内部路径；日志中的敏感字段脱敏。

## 验证

对涉及的风险点用具体输入验证拒绝路径（越权访问、恶意文件名、内网 URL、过期或篡改令牌），不能只验证正常路径。静态扫描结果与实际攻击面验证分别报告。
