# Spring Boot 运行、发布与故障排查

适用范围：应用构建产物、启动参数、健康检查、停机、发布回退或运行资源变更。约束依据目标部署环境和项目发布流程确定；不预设容器或编排平台。

## 构建与运行

- 验证目标产物格式、构建来源、依赖和目标 JDK。可执行 JAR、WAR、容器镜像或其他交付形式以项目为准；IDE 启动成功不构成目标产物验证。
- JVM 参数和应用参数依据实际启动命令配置。`java -jar` 启动时，JVM 参数位于 `-jar` 之前，应用参数位于归档路径之后；容器和外部应用服务器遵循各自的启动机制。
- `-Xmx` 限制 Java 堆，不代表进程总内存上限。资源评估还应覆盖 Metaspace、直接内存、线程栈、原生库和容器/操作系统限制。
- 运行参数按真实配置来源注入。必要配置无效时应显式失败；敏感配置通过受控渠道注入，不写入镜像或普通日志。

## 健康、停机与故障恢复

- 存活、就绪和业务功能探测具有不同含义。共享依赖故障按其业务影响处理，不将所有依赖失败映射为重启应用。
- 管理端点按运维需要开放，并限制网络和身份访问范围。端口连通、启动日志或健康端点成功均不足以证明业务请求可用。
- 停机流程应覆盖入口摘流、就绪状态传播、正常停止信号、进行中的请求和后台任务。Spring 生命周期、外层进程终止时限及依赖超时预算须协调。
- 运行排查记录版本、实例、时间、请求范围和实际响应层。线程、连接池、堆、原生内存、队列及共享资源应结合指标、日志和请求关联信息分析。

## 发布与回退

- 发布记录应关联产物、源码版本、配置要求和数据结构版本。验证真实入口、代表性业务结果及依赖连接。
- 滚动发布期间核对新旧版本对接口、数据库结构、缓存结构和后台任务的兼容性。应用包回退不自动撤销数据库迁移或已提交业务数据。
- 按可用性、规模和故障恢复目标选择滚动、蓝绿或小流量发布。未采用容器、编排或发布平台时，不引入无关平台作为前置条件。
- 回退方案应定义触发条件、执行责任、数据兼容和用户影响。未执行的发布、停止或回退操作须标记为未验证。

## 验证

在隔离或目标验证环境检查运行版本、生效配置、真实入口和业务结果。涉及停机、依赖故障、超时任务或版本兼容时，覆盖相应恢复路径。语法、构建和健康检查结果分别记录，不相互替代。
