# Spring Boot 运行、发布与故障排查

适用：构建产物、启动参数、健康检查、停机、发布回退、运行资源。依据目标部署环境和项目的发布流程，不预设容器或编排平台。

## 构建与运行

- 验证目标产物的格式、构建来源、依赖、目标 JDK。可执行 JAR、WAR、容器镜像等以项目为准。IDE 里能启动，不等于目标产物已验证。
- JVM 参数和应用参数，按实际启动命令配置。`java -jar` 时：JVM 参数在 `-jar` 之前，应用参数在归档路径之后。容器和外部应用服务器按各自的启动机制。
- `-Xmx` 只限制 Java 堆，不是进程总内存上限。资源评估还要看 Metaspace、直接内存、线程栈、原生库、容器或操作系统的限制。
- 运行参数从真实的配置来源注入。必要配置无效时显式失败。敏感配置通过受控渠道注入，不写进镜像或普通日志。

## 健康、停机、恢复

- 存活、就绪、业务功能探测，含义不同。共享依赖故障按业务影响处理，不要把所有依赖失败都映射成"重启应用"。
- 管理端点按运维需要开放，并限制网络和身份范围。端口通、启动日志正常、健康端点成功，都不能证明业务请求可用。
- 停机流程要覆盖：入口摘流、就绪状态传播、正常的停止信号、进行中的请求、后台任务。协调好 Spring 生命周期、外层进程的终止时限、依赖的超时预算。
- 运行排查时记录：版本、实例、时间、请求范围、实际响应在哪一层。线程、连接池、堆、原生内存、队列、共享资源，要结合指标、日志、请求关联信息分析。

## 发布与回退

- 发布记录要关联：产物、源码版本、配置要求、数据结构版本。验证真实入口、有代表性的业务结果、依赖连接。
- 滚动发布期间，核对新旧版本在接口、数据库结构、缓存结构、后台任务上的兼容。应用包回退不会自动撤销数据库迁移或已提交的业务数据。
- 按可用性、规模、恢复目标选滚动、蓝绿或小流量发布。没有用容器、编排、发布平台，就不要引入无关平台当前置条件。
- 回退方案要定义：触发条件、执行责任、数据兼容、用户影响。没执行的发布、停止、回退操作，标记为未验证。

## 验证

在隔离环境或目标验证环境检查：运行版本、生效配置、真实入口、业务结果。涉及停机、依赖故障、超时任务、版本兼容时，覆盖相应的恢复路径。语法检查、构建、健康检查分别记录，不相互替代。
