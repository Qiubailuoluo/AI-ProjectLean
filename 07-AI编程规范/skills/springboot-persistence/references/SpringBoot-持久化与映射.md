# Spring Boot：持久化与映射

适用：持久化访问、数据对象映射、数据模型边界。使用 Repository 等抽象时，保留等效职责，不新增同义的访问层。

## Mapper / Repository

职责：持久化访问和数据映射。

- 明确查询条件、字段映射、返回数量、空结果的语义。接口、SQL/XML、Java 类型保持一致，不依赖偶然的字段匹配或隐式转换。
- 更新结果按具体 SQL 和驱动的返回约定解释。条件更新的影响行数，要结合唯一标识、更新条件、返回语义来判断。
- Mapper 只做数据访问，不组织 HTTP 响应。
- 跨模块的数据访问遵守所属模块的边界。SQL 能访问到，不是绕过业务规则的理由。
- 用 MyBatis 时：SQL 值用参数绑定，动态标识符用固定映射。安全要求见[MyBatis 参数绑定与动态 SQL](SpringBoot-MyBatis与动态SQL.md)。

## Entity

这里的 Entity 指持久化实体（PO），按项目的存储映射方式维护。采用领域模型时，职责由领域边界确定。

- 主键、字段类型、可空性、生成方式，要和数据库及映射配置一致。数据库默认值是否生效，按实际的 INSERT 行为判断。
- 区分"客户端可写"和"服务端或存储层维护"的字段，防止批量赋值覆盖内部状态。对外输出遵循 DTO 的字段边界。
- 历史快照按业务语义确定。当前的关联数据，不代表历史时点的值。
