# Spring Boot：配置、依赖与构建

适用：配置、日志、依赖、构建的变化。Maven、Gradle、自定义流水线，JAR、WAR、镜像等选择，服从项目目标。本文不规定统一的命令、文件格式或打包方式。

## 配置与环境

- 核实 Spring Boot、JDK、构建工具、依赖的版本和兼容条件。版本升级要有明确需求，并评估影响。
- 区分各环境的资源地址、权限、数据。Profile 名称不能证明测试已隔离，要核实生效配置和目标资源。
- 敏感值通过项目受控的渠道注入。
- 必要配置缺失或无效时，应显式失败。不要把故障映射成空数据或成功。
- 日志要能关联业务和请求。避免重复堆栈，避免泄露敏感数据。
- 只是为本机启动或调试而改配置：使用 `git-delivery`，读「本地运行配置」。优先用外部覆盖的方式，标明仅本地内容，核对提交和打包的边界。

## 依赖与构建

- 分析直接依赖、传递依赖、版本管理、实际解析结果。复用项目已有的构建入口、版本管理、打包方式。
- 依赖升级只限于变更所需的范围，并检查冲突、解析结果、兼容性。版本新，不等于兼容。
- 工具、配置格式、打包方式的变更，要符合兼容条件和交付目标。按变更范围引入必要的能力，不为一次修改引入一整套新平台。
- 靠日志、指标、业务证据定位问题。临时调高日志级别，要定义怎么恢复。不要长期用 DEBUG 记录全部请求。

## 验证

- 配置变更：核对来源和实际目标。
- 依赖变更：核对解析结果和受影响的兼容行为。
- 构建与运行结果分别记录，不要把"构建通过"说成"测试通过"。测试设计使用 `springboot-testing`。
