# Spring Boot：Service 与模块协作

适用范围：业务入口、规则编排、权限判断、模块协作或异步任务变更。条款仅适用于本次变更涉及的行为；示例不定义目标业务。

## Service

负责业务规则、操作权限、流程编排和必要的事务协调；业务入口应能说明输入前提、输出和失败条件。

### 输入、校验与安全

- 消息、任务等非 HTTP 入口不经过 HTTP 参数校验流程。各入口应验证可信输入，并在业务边界维护数量范围、可用状态及合法状态迁移等不变量。
- 身份与权限判断依据调用入口：HTTP 请求使用可信认证上下文；任务和消息使用可信调用上下文。客户端自报身份不构成认证结果。
- 权威业务计算由后端规则完成。历史记录按业务语义保存必要快照，不以客户端提交的最终结果作为权威值。

### 模块协作

- 跨模块调用应表达明确业务能力并保留被调用模块的业务规则。`getById` 等查询方法不隐含状态或权限校验；同进程协作可通过 Java 调用实现。
- 多模块协作应明确规则归属、数据写入责任和失败语义。通过模块公开的业务入口协作，不直接修改其他模块数据或依赖其内部实现。跨模块调用本身不建立独立事务或分布式事务。
- 单一实现可使用具体 Service 类；仅在存在替换需求或明确协作边界时引入接口。新增 Service、helper 或组件前按[代码复用与注释](../../engineering-baseline/references/代码复用与注释.md)评估已有实现和复用边界。

### 事务与外部操作

涉及多步写入、并发竞争、重复请求或外部副作用时，按需参考[事务、并发与幂等](../../springboot-transactions/references/SpringBoot-事务并发与幂等.md)。事务注解本身不足以证明全部操作受事务保护。

### 异步与非 HTTP 入口

消息消费者、定时任务和批处理可作为独立入口。目录按项目运行模型确定；入口复用相应业务规则，不限定目录名称。

- 异步执行核对实际执行器、并发和积压上限、拒绝策略、处理超时及停机行为。队列、线程或虚拟线程数量增加不代表数据库和外部依赖容量增加；不得用无限队列掩盖过载，也不默认选用会阻塞调用线程的拒绝策略。
- 默认代理模式下，同对象内部调用不触发 `@Async` 拦截。请求线程的事务、认证/租户及日志上下文不假定自动跨线程传播；按现有机制传递必要的可信值并在任务结束清理，避免线程复用串租户。
- 接收任务不等于任务成功；异步异常须可观察。定时任务核对多实例及重叠执行，消息核对确认、重复投递和失败恢复；仅在业务要求时选择互斥或持久化任务机制。必须在重启后继续的工作不能只保存在进程内存。

参考：[Spring 任务执行与调度](https://docs.spring.io/spring-framework/reference/integration/scheduling.html)。
