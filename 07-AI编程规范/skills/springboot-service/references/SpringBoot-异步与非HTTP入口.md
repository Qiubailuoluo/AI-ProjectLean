# Spring Boot：异步、定时任务与消息入口

适用：`@Async`、线程池、消息消费者、定时任务、批处理。消息消费者、定时任务、批处理是独立入口，目录按项目运行模型定，入口复用相应的业务规则。

## 异步执行

- 核对实际的执行器、并发上限、积压上限、拒绝策略、处理超时、停机行为。
- 队列、线程、虚拟线程的数量变多，不代表数据库和外部依赖的容量变大。
- 不用无限队列掩盖过载。也不默认选择会阻塞调用线程的拒绝策略。

## 上下文

- 默认代理模式下，同一对象内部调用不触发 `@Async` 拦截。
- 请求线程的事务、认证、租户、日志上下文，不假定会自动传到其他线程。
- 需要时，按现有机制把必要的可信值传过去，并在任务结束时清理，避免线程复用导致串租户。

## 结果与重复执行

- 接收任务不等于任务成功。异步异常要能被观察到。
- 定时任务：核对多实例、重叠执行。消息：核对确认、重复投递、失败恢复。
- 只有业务要求时，才选互斥或持久化任务机制。
- 必须在重启后继续的工作，不能只保存在进程内存里。

参考：[Spring 任务执行与调度](https://docs.spring.io/spring-framework/reference/integration/scheduling.html)。
