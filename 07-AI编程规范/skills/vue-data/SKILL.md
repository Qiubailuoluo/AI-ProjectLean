# Vue 请求与状态

改动前先看现有请求客户端、接口类型、状态管理、缓存方案和后端契约。

## 核心规则

- 请求统一走项目已有的请求客户端，不在组件里散落新的 fetch/axios 实例。
- 字段、状态码、分页、错误结构以后端实际契约为准，不只依据前端类型定义。
- 防请求竞态：晚到的响应不得覆盖新状态；组件卸载、切换会话时取消或忽略在途请求。
- 429、超时、网络失败要给出可理解的反馈；不静默重试写操作。
- 预签名 URL 等第三方凭据请求不携带业务鉴权头，响应也不按业务 JSON 解析。
- token 不进日志、不放 URL。

## 按需读取

- 请求封装、接口数据、共享状态、客户端缓存：[请求与状态](references/请求与状态.md)
- 文件上传、下载、资源发布：同时使用 `file-upload-download`
- 文件直传用 MinIO：同时使用 `minio-file-lifecycle`；用其他存储时，核对对应服务的契约
- 429、异常请求、人机验证：[请求防滥用与资源边界](../engineering-baseline/references/请求防滥用与资源边界.md)
- 鉴权状态与退出：同时使用 `vue-navigation`
- 接口字段、错误码、分页约定：同时使用 `api-contract`

## 验证

核对前后端字段、状态码、分页、上传方式、失败语义。不能只依据前端类型推断服务端行为。
