# Vue 共享状态、缓存与上传交互

适用：Store、客户端缓存、身份切换后的状态清理、上传下载的前端流程。请求本身的处理见[请求与状态](请求与状态.md)。

## 状态归属

- 组件局部状态留在使用处。多个视图共享、且生命周期明确的数据，再放进项目已有的 Store。
- 区分：服务端权威数据、客户端草稿、展示派生值。不复制多份可变的权威状态。
- 创建、更新、删除之后，按已有的请求和缓存策略，更新或失效相关视图。
- 失败、回滚、部分成功时，不能把乐观结果当作已提交的事实。

## 身份与缓存隔离

- Store 里的用户或租户数据，在身份切换和退出时，按契约清理。
- 缓存 Key 和读取权限，要覆盖实际的隔离维度。缓存命中，不能代替后端授权。
- 清空状态，拦不住在途请求随后写回。身份切换时，要让旧会话的请求失效。结果写入前，核验当前会话与请求的归属。
- 取消请求只是辅助。不能假定旧的回调都不会执行。成功、失败、完成回调里的数据、加载状态、错误、会话刷新结果，都要遵守这条边界。

## 凭据

访问令牌、预签名 URL、敏感内容，按凭据处理。存储位置、跨站请求策略、刷新机制，依据现有认证架构确定，不由通用 Skill 指定一种方案。

## 文件交互

- 直传、代理上传、下载的请求方法、签名头、大小限制、完成确认，按实际的后端或对象存储契约实现。
- 客户端的上传进度或成功回调，证明不了业务记录已绑定。
- 私有签名 URL，不写进日志、分析事件、长期状态。

## 验证

覆盖：身份切换后旧请求的写回、缓存失效、上传的部分失败。第三方请求要核对实际发出的凭据和签名头。

官方参考：[Pinia Store](https://pinia.vuejs.org/core-concepts/)、[Vue 安全指南](https://vuejs.org/guide/best-practices/security.html)。
