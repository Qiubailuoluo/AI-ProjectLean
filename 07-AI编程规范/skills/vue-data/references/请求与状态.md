# Vue 请求与异步状态

适用：HTTP 请求、数据加载、接口契约对接。请求库、状态管理、缓存方案以目标项目为准。不要因为本文新增 Pinia、Axios 或其他依赖。共享状态、缓存、上传见[共享状态与缓存](共享状态与缓存.md)。

## 接口契约

- 依据后端接口契约，核对：方法、路径、字段、可空性、单位、分页、错误码、认证方式。
- 前端类型、Mock、开发代理配置，不是真实接口的证据。
- 接口格式变更，要同步检查后端实现、前端调用方、兼容期。

## 请求入口

- 复用项目已有的客户端约定，集中处理：基础地址、认证凭据、超时、序列化、通用错误映射。
- 业务请求保留可辨识的输入输出类型。不为统一格式，重复包装每一层调用。
- 请求层保留接口字段的语义，不承载页面文案和展示映射。
- 按目标服务划分凭据和拦截器的作用域，核对最终请求地址。
- 第三方 API、预签名上传和下载，不能自动附带本项目的访问令牌，也不能套用业务响应解析。请求头、Cookie、跨域行为，分别按目标契约配置。

## 响应与错误

- 成功、错误、分页的格式，要与已确认的后端契约一致。
- 区分：HTTP 状态和业务错误码、空响应、文件流、普通 JSON。
- 只在接口确实使用统一响应体时，才解析该结构。不假设所有请求都返回固定的 `code/message/data`。
- 区分：网络故障、认证失效、权限拒绝、业务冲突、结果未知。业务错误由调用场景决定怎么展示、怎么恢复。
- 全局拦截器和页面要明确谁负责展示错误，避免同一个失败弹两次。字段提示和表单摘要，可按交互需要配合。

## 乱序与重试

- 加载中的旧请求，可能晚于新请求返回。搜索、筛选、分页、切换详情时，用项目已有的取消或结果归属机制，避免过时的响应覆盖当前视图。
- 有副作用的请求，只在"结果可确认、业务允许"时自动重试。
- 超时不能证明请求没有执行。提交按钮防重，替代不了后端幂等。

## CSRF

使用 Cookie 等浏览器自动携带的凭据时，使用 `engineering-baseline`，读「工程底线」，核对状态变更的 CSRF 防护。前端按既有协议传递必要的凭据，服务端独立验证。验证合法提交，以及缺失或伪造防护信息时的拒绝行为。不要因为跨域请求受 CORS 限制，就推定安全。

## 验证

- 覆盖：接口字段、状态码和业务错误的映射、空响应、文件流、请求乱序、重复提交。
- 联调时核对网络请求和服务端结果。Mock 只验证前端分支。
- 涉及 Spring Boot 接口变更时，同时使用 `springboot-api`，读「接口与异常」。

官方参考：[Fetch 凭据与取消请求](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)、[OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
