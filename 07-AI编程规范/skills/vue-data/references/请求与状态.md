# Vue 请求、共享状态与接口契约

适用范围：HTTP 请求、数据加载、共享状态、客户端缓存和上传流程。请求库、状态管理与缓存方案以目标项目为准；不得因本参考新增 Pinia、Axios 或其他依赖。

## 接口与异步状态

- 依据后端接口契约核对方法、路径、字段、可空性、单位、分页、错误码及认证方式。前端类型、Mock 和开发代理配置不构成真实接口证据；兼容变化需检查现有调用方。
- 项目内请求入口应复用既有客户端约定，集中处理基础地址、认证凭据、超时、序列化及通用错误映射。业务请求保留可辨识的输入输出类型；不得为统一格式而重复包装每层调用。
- 按目标服务划分凭据与拦截器作用域，核对最终请求地址。第三方 API、预签名上传和下载不得自动附带本项目的访问令牌或套用业务响应解析；分别按目标契约配置请求头、Cookie 和跨域行为。
- 响应成功、错误和分页格式应与已确认的后端契约一致。区分 HTTP 状态与业务错误码、空响应、文件流和普通 JSON；仅在接口确实使用统一响应体时解析该结构，不假设所有请求都返回固定的 `code/message/data`。
- 全局拦截器与页面应明确错误展示责任，避免同一失败重复弹窗；字段提示与表单摘要可按交互需要配合。接口格式变更应同步检查后端实现、前端调用方及兼容期。
- 请求层保留接口字段语义，不承载页面文案或展示映射。
- 请求封装承载稳定的协议处理。业务错误由调用场景决定展示与恢复方式；区分网络故障、认证失效、权限拒绝、业务冲突和结果未知。
- 加载中的旧请求可能晚于新请求返回。搜索、筛选、分页及切换详情时，使用项目已有取消或结果归属机制，避免过时响应覆盖当前视图。
- 具有副作用的请求仅在结果可确认且业务允许时自动重试。超时不证明请求未执行；提交按钮防重不能替代后端幂等。

使用 Cookie 等浏览器自动携带的凭据时，按[工程底线](../../engineering-baseline/references/工程底线.md#通用要求)核对状态变更的 CSRF 防护；前端按既有协议传递必要凭据，服务端独立验证。验证合法提交与缺失或伪造防护信息时的拒绝行为，不因跨域请求受 CORS 限制就推定安全。

## 数据归属与缓存

- 组件局部状态保留在使用处；多个视图共享且生命周期明确的数据再放入项目既有 Store。区分服务端权威数据、客户端草稿和展示派生值，不复制多份可变权威状态。
- Store 中的用户或租户数据在身份切换与退出时按契约清理；缓存 Key 与读取权限覆盖实际隔离维度。缓存命中不替代后端授权。
- 清空状态不阻止在途请求随后写回。身份切换时使旧会话请求失效，结果写入前核验当前会话与请求归属；取消请求只是辅助，不能假定旧回调均不会执行。成功、失败和完成回调中的数据、加载状态、错误及会话刷新结果均须遵守该边界。
- 创建、更新和删除后按已有请求/缓存策略更新或失效相关视图；失败、回滚和部分成功时不得直接把乐观结果当作已提交事实。
- 访问令牌、预签名 URL 和敏感内容按凭据处理；存储位置、跨站请求策略及刷新机制依据现有认证架构确定，不由通用 Skill 指定一种方案。

## 文件交互与验证

直传、代理上传及下载的请求方法、签名头、大小限制和完成确认按实际后端/对象存储契约实现。客户端上传进度或成功回调不证明业务记录已绑定；私有签名 URL 避免写入日志、分析事件或长期状态。

按变更范围验证接口字段、状态码与业务错误映射、空响应和文件流、请求乱序、重复提交、身份切换后的旧请求写回、缓存失效及上传部分失败。第三方请求核对实际发出的凭据与签名头。联调时核对网络请求和服务端结果；Mock 仅验证前端分支。涉及 Spring Boot 接口变更时按需结合[接口与异常](../../springboot-api/references/SpringBoot-接口与异常.md)。
