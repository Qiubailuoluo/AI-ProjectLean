# Vue 路由、会话与页面访问

适用范围：路由表、导航守卫、登录恢复、菜单、退出或页面权限。Router 版本及导航 API 以项目依赖为准。

- 路由元数据和菜单控制页面体验，不构成后端资源授权。服务端应基于可信身份核验受保护操作；前端隐藏入口不能证明请求无权访问。
- 导航守卫应区分未登录、会话待恢复、已登录但无权及系统故障。避免循环重定向、重复请求和刷新后短暂展示受限页面。
- 登录后的返回地址默认限定为应用内可信目标；跨站单点登录等已确认流程依据受控目标白名单校验，不能直接采用用户提供的任意地址。退出或身份切换时清理相关请求、页面与共享状态，并按[请求与状态](../../vue-data/references/请求与状态.md)阻止旧会话回调写入。
- 401、403、404 和网络失败分别依据后端契约处理；过期恢复失败不应无限重试。授权信息变化时核查已打开页面和共享缓存的可见状态。
- 路由参数是外部输入。详情页面仍需处理资源不存在、已删除、越权及直接访问；路由参数存在不代表资源可访问。
- 使用 History 模式及非根路径部署时，构建 `base`、路由基础路径和静态服务回退须一致。静态资源请求与 API 请求不能被无条件回退到应用入口。

验证直接访问、刷新、返回、登录过期、越权、切换用户及无效目标 URL。涉及代理路径时按需读取 [Nginx Skill](../../nginx-proxy/SKILL.md)；同时核对后端真实权限边界。

官方参考：[Vue Router 导航守卫](https://router.vuejs.org/guide/advanced/navigation-guards.html)、[History 模式与服务端配置](https://router.vuejs.org/guide/essentials/history-mode.html)。
