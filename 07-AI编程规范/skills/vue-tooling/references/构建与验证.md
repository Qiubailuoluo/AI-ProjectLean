# Vue 构建、配置与验证

适用：依赖、环境配置、构建产物、部署入口、前端测试的变更。以项目现有的包管理器、构建器、脚本、部署目标为准。

## 依赖与构建

- 核对 Vue、Router、状态管理、组件库、构建器的实际版本和兼容关系。沿用锁文件和项目脚本。
- 单项变更，不自动升级整套前端依赖。

## 环境与配置

- 开发服务器代理，只说明本地开发的请求路径。生产的 API 地址、跨域、反向代理、静态资源路径，按实际部署另行核验。
- 浏览器能拿到的构建变量和打包产物，不能包含密钥。Vite 只暴露 `VITE_` 前缀的变量，且这些值会被打进产物；不想暴露的变量不要用这个前缀。
- Vite 环境变量优先级：启动时已存在的系统环境变量最高，其次依次是 `.env.[mode].local`、`.env.[mode]`、`.env.local`、`.env`；`.local` 文件只放本机配置，不提交；修改 `.env` 后要重启开发服务器。`NODE_ENV` 与 mode 是两个概念。
- 构建期变量变化，通常需要重新构建。配置来源、模式、生效值，按目标构建器核实。
- 只为本机启动而调整环境、代理、脚本时，使用 `git-delivery`，读「本地运行配置」。个人覆盖和共享修复分别处理。不能因为文件没提交，就推定构建不会加载它。

## 静态资源与发布

- 静态资源基础路径、Router History 模式、托管服务的路由回退，共同决定刷新和直接访问的结果。
- 版本发布还要核对：缓存策略，以及旧页面引用新旧静态资源时的兼容性。

## 验证选择

- 组件和状态逻辑：按风险选单元测试或组件测试。路由、接口、登录、关键表单流程：按需用集成测试或浏览器验证。
- Mock 只证明"被模拟的边界内"的前端行为。
- 类型检查、格式检查、构建、测试、预览、目标环境，分别记录结果。构建成功，不能证明接口、权限、代理路径正确。
- 跨前后端的改动，核对：请求与响应契约、错误语义、认证状态、上传完成、真实的部署入口。只靠前端 Mock 或开发服务器代理，不足以证明联调完成。

官方参考：[Vue 测试指南](https://vuejs.org/guide/scaling-up/testing.html)、[Vite 环境变量与模式](https://vite.dev/guide/env-and-mode)、[Vue Router History 模式](https://router.vuejs.org/guide/essentials/history-mode.html)。Vite 规则只在项目实际使用 Vite 时适用。
