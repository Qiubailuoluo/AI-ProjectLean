# 样式、文件拆分与局部重构

适用：重复的样式、单文件职责混杂、长流程因局部补丁持续膨胀。目录和组件复用见[页面组织与复用](页面组织与复用.md)。

## 样式

- 同模块重复的字号、字重、间距、颜色、交互状态，复用项目已有的设计令牌、CSS 变量、SCSS 变量、模块样式。令牌按职责命名，不用页面位置或偶然的数值命名。
- 组件局部样式留在组件范围。模块共用的样式，集中到既有的样式入口。
- `scoped` 只限定选择器的影响范围，不会自动实现跨组件复用。
- 避免用层层 `:deep()` 覆盖组件库的内部结构，来维持一致性。

## 单文件拆分

单文件同时承载大量 API 调用、状态编排、纯计算、复杂模板、重复样式时，按职责拆：

- 视图和交互：留在 `.vue`。
- 稳定的业务数据访问：放进现有的 API 层。
- 可复用的有状态逻辑：放进项目支持的组合函数或等效机制。
- 纯函数：放进合适的模块。
- 样式：按复用范围归属。

抽取后，保留清晰的数据流和生命周期清理。不因为文件超过固定行数就拆，也不为每个方法新建文件。拆分要能减少重复、降低修改的影响面，并让调用方更容易定位行为。

## 长流程与局部重构

- 变更流程前，追踪：入口、状态变化、请求、错误处理、退出路径。识别重复的分支、隐式共享状态、每次修改都会碰到的节点。
- 在本次需求范围内，先整理清晰的步骤、状态归属、失败恢复，再接入新行为。
- 如果最小补丁会进一步复制规则，或扩大条件链，就完成必要的局部重构。跨模块的架构调整，需要另有需求或证据。
- 区分"需求要求的行为变化"和"结构整理"。纯重构的部分，保留原有的接口、可见行为、权限边界。
- 注释记录非显然的状态约束和设计原因。不为旧补丁保留已失效的说明。

## 验证

核对：抽取前后的页面显示、交互状态、共享组件的调用方、模块样式、主要流程分支。校验无效输入不会发出请求，失败后状态可恢复。

参考：[单文件组件 CSS 作用域](https://vuejs.org/api/sfc-css-features.html)、[组合函数](https://vuejs.org/guide/reusability/composables)。
