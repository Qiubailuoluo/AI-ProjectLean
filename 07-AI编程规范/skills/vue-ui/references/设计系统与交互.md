# Vue 设计系统与交互

适用：新增或调整页面视觉、色彩、组件库、交互反馈、动画。依据产品目标、现有设计系统、目标用户确定方案。本文不规定统一的视觉风格，也不规定必须采用的组件库。

## 视觉体系

- 实施前核查：现有页面、设计稿、主题令牌、组件库、图标资源。
- 已有体系能满足需求时，扩展相应的变量和组件。新页面要和同模块保持一致：字体层级、间距、圆角、边框、图标、控件状态。
- 颜色按角色维护，如背景、文字、边框、主操作、成功、警告、错误。明确明暗主题下的语义映射。不在各页重复硬编码颜色和字号。
- 主次信息用层级、留白、对比度表达。颜色不能是状态的唯一提示。
- 新建或重塑视觉体系时，先确定内容层级、使用场景、品牌约束，再选字体、配色、布局。
- 动画、渐变、装饰不能掩盖操作重点。对比度和焦点状态，依据项目的无障碍目标核验。

## 组件与开源方案

- 优先核查项目已安装的组件库和封装。
- 缺少能力时，再查候选库的：官方文档、GitHub 仓库、目标 Vue 版本的兼容性、维护状态、许可证、无障碍能力、主题定制、引入成本。不能只凭 Star 数或示例截图决定采用。
- Element Plus 是 Vue 3 的候选组件库，提供表单、弹窗、主题能力。项目用 Vue 2 或其他体系时，按对应版本和迁移成本选择。
- 不要为一个控件，并列引入多套职责重叠的组件库。
- 开源组件、图标、样式，要遵循许可证和来源要求。复用其公开 API 和主题变量。需要大量依赖内部 DOM 结构，或反复深层覆盖样式时，重新评估选型或封装边界。

## 交互反馈

- 有异步处理或副作用的操作，要明确：触发、进行中、成功、失败、适用的恢复方式。
- 提交、删除、耗时操作要给及时反馈。
- 操作确认、撤销、错误恢复，依据后果设计。破坏性操作要给出清晰的对象和影响，不能只靠按钮颜色或动画表达风险。

## 动效

- 动画用来解释状态或空间关系，不能代替结果提示。
- 转场和微动效，遵循现有节奏并保持克制。避免连续、重复、阻断操作的动画。
- 保证键盘和触控操作可用。在"减少动态效果"偏好下，提供低动态或无动画的路径。

## 验证

- 对照同模块既有页面，核对组件状态、字体、颜色、间距。
- 在目标尺寸和输入方式下，检查：布局、焦点、对比度、动画关闭、关键流程的反馈。
- 新引入依赖时，记录：版本、许可证、用途、实际验证过的集成能力。
