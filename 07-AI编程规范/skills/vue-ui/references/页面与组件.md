# Vue 页面、组件与表单

适用：页面结构、组件契约、表单交互、模板渲染。使用 Vue 2/3、Options/Composition API、组件库时，遵循目标项目已确认的版本和约定。

## 组件边界

- 组件承担明确的展示或交互职责。
- 新增抽象前，核查现有组件、组合函数、设计系统。外观相同，不足以证明行为契约相同。
- 明确 props、事件、双向绑定的输入输出语义。输入数据的归属和修改方式，遵循所用的 Vue 版本。
- 派生值优先写成可追溯的计算结果。有副作用的侦听，要处理重复执行和失效清理。
- 列表使用稳定且唯一的业务键。分页、筛选、视图切换时，核对组件状态是否被错误复用。
- 弹窗、表单、页面离开时，清理只属于该实例的订阅和异步副作用。

## 字段语义

- 同一个后端字段出现在多个页面时，核对：业务含义、单位、状态、值域。
- 语义相同的显示名称、格式、选项，从已有的字段定义或展示映射复用。语义确有差异时，按页面上下文命名，不为消除重复而强制统一。
- 后端字段名，不直接当界面文案。

## 表单

- 按当前需求和接口契约，校验：必填、格式、范围、长度、跨字段关系。
- 在发请求之前，拦截明确无效的输入，给字段级的反馈。校验要覆盖实际提交的值，不能只限制输入控件。
- 数量、价格、权限、状态迁移等权威规则，仍由后端核验。前端禁用提交按钮，不提供请求幂等。

## 状态与安全

- 加载、空数据、失败、处理中、成功，各状态要和实际的请求结果对应。
- 失败时保留可恢复的输入。避免重复提交，避免把旧数据误显示成新结果。
- 文本由框架做安全插值渲染。使用原始 HTML、外部 URL、第三方内容时，核查信任来源和渲染风险。不把用户输入直接编译成模板。
- 绑定用户提供的 URL（`:href`、`:src`）前，要确认协议是 `http`、`https` 等白名单，防 `javascript:`。官方建议由后端在保存前清洗，前端清洗只是补充。
- 允许用户控制样式时，用 `:style` 的对象语法，只开放安全的属性（如颜色）。不绑定用户提供的整段 CSS，也不绑定 `onclick` 等事件属性的字符串。
- 不要把 Vue 挂载到含有服务端渲染的用户内容的节点上，用户提供的 HTML 可能被当成模板执行。
- 按现有交互体系，保留：键盘操作、可见焦点、字段标签、错误提示、状态反馈。图标和颜色，不能是关键状态的唯一表达方式。

## 验证

- 按变更范围覆盖：同字段跨页面展示、合法与无效输入、拦截后的请求数量、异步成功与失败、重复操作、组件复用、键盘交互。
- 只是视觉呈现的变更，按影响选验证，不自动引入全部接口或后端测试。
