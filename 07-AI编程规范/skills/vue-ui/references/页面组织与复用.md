# Vue 页面组织与复用

适用：项目结构与命名、模块依赖、重复组件、跨页面展示不一致。依据现有设计系统、模块边界、真实的重复行为，决定抽取范围。文件行数只是检查信号，不是强制拆分的阈值。样式拆分和长流程重构见[样式、文件拆分与局部重构](样式与文件拆分.md)。

## 目录与模块

- 沿用现有的业务模块和技术目录约定。
- 页面负责路由级编排。模块维护自己的组件、数据访问、状态、规则。跨模块共享的能力，仅在契约稳定且确有复用时上移。
- 不强制新建一套目录，也不套用后端的 MVC/DDD 名称。

## 依赖

- 模块之间通过明确的公共入口调用。不深层导入其他模块的私有页面、内部状态、实现细节。
- 共享基础层不反向依赖业务页面。检查循环依赖，和宽泛的聚合导出造成的耦合。
- 接口访问、环境配置、样式令牌，保持明确的入口。页面里不散布重复的基础地址、令牌处理、跨模块私有规则。

## 命名

- 组件、组合函数、类型、样式、资源的命名，遵循项目已有规则，名称表达业务职责。同一个概念，命名保持一致。
- 避免用 `common`、`utils`、`data` 等宽泛名称，堆积无关能力。
- 适用版本的官方命名规则，与既有约定冲突时，核对工具约束后再决定，不批量改名。
- 移动或重命名后，核查：路由懒加载、导入路径、大小写敏感的环境、已有的公开入口。

## 组件复用

- 修改前，搜索同模块和共享目录里已有的：组件、组合函数、字段展示映射、样式变量。
- 比较输入、输出、状态、交互、权限条件。契约相同，就复用或扩展既有实现。
- 多个页面重复的结构和交互，可抽成组件。变化的部分，用明确的 props、事件、slot 表达。页面特有的业务分支，留在页面或所属模块。
- 避免把所有差异做成大量布尔开关，避免创建职责过宽的通用组件。
