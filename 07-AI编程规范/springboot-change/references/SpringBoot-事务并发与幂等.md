# Spring Boot 事务、并发与幂等

适用范围：数据库原子性、并发控制、重复请求处理或失败恢复变更。条款适用性取决于目标事务管理器、传播与回滚配置；代理行为说明以 Spring 默认代理模式为前提。

## 事务边界与失败语义

- 定义须共同提交或回滚的数据库操作及事务入口。跨业务包或 Service 调用本身不切断同一线程、同一事务管理器管理的事务；跨数据源、线程或远程服务不得假定仍处于同一事务。
- 默认代理模式仅拦截经代理进入的调用。同一对象内部调用不会触发新的事务拦截，但已有外层事务仍可覆盖内部数据库访问。自行 `new` 的对象不具有 Spring 容器代理行为。
- 回滚结果由异常类型、事务属性和事务状态共同决定。异常被捕获并正常返回时，事务可能提交；已标记为 `rollback-only` 的事务也可能在提交阶段失败。日志记录或统一异常处理不足以证明最终事务结果。
- 将慢外部调用移出短数据库事务时，拆分为 `private` 方法不改变代理边界。应依据项目机制调整事务入口或采用编程式事务，并定义外部调用失败后的恢复语义。

## 并发与业务不变量

- 定义并发条件下必须成立的业务不变量，并选择可维护该不变量的机制。事务本身及查询后更新均不自动消除竞争条件。
- 条件更新、行锁和唯一约束按数据模型及业务语义选择。条件更新应覆盖不变量本身，并核对输入范围、影响行数和同事务内相关记录。
- “查询不存在后插入”存在竞争窗口。采用唯一约束或持久化去重时，按具体约束冲突分类；其他数据库错误不得映射为重复请求。
- 失败事务回滚后，竞争结果的后续读取应位于可读取最终状态的事务边界中。

## 请求重试与幂等

- 当重复执行会造成错误或不可接受后果，且调用方可能重试时，定义幂等标识及结果保留机制。标识生成方、唯一范围、有效期和结果查询方式由接口与业务语义确定。
- 同一操作的重试复用同一标识；新操作使用新标识。同一标识关联不同请求内容时应返回冲突，不得复用另一请求的结果。
- Redis 占位、前端禁用控件和网络重试策略不足以单独提供持久化去重保证。持久化约束与结果保留时长按所需保证和恢复方式确定。

## 外部副作用与恢复

- 数据库回滚不撤销 Redis 写入、对象存储操作、通知或已提交的其他事务。超时或响应丢失会产生结果不确定性；重试或补偿前应具备状态确认路径。
- 外部副作用必须最终完成时，可将业务记录和待执行任务写入同一数据库事务，再由后台处理器重试。任务应使用稳定事件标识并允许重复投递。提交后回调或内存事件不提供进程重启后的持久化保障。
- Outbox、分布式锁和独立编排层均为可选机制；按一致性目标、故障模型和现有基础设施评估。

## 验证

按风险覆盖中途失败后的最终数据、并发交错、重复标识、同标识不同内容及提交成功但响应丢失后的恢复。验证真实 SQL、约束或事务行为时，使用匹配的测试资源，并在业务事务结束后核对最终数据。Mock 影响行数不构成数据库行为证据。
