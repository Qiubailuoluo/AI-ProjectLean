# Vue 设计系统与交互

适用范围：新增或调整页面视觉、色彩、组件库、交互反馈或动画。依据产品目标、现有设计系统和目标用户确定方案；本参考不规定统一视觉风格或必须采用的组件库。

## 视觉体系

- 实施前核查现有页面、设计稿、主题令牌、组件库和图标资源。已有体系能满足需求时扩展相应变量与组件；新页面应维持同一模块的字体层级、间距、圆角、边框、图标和控件状态。
- 颜色按角色维护，例如背景、文字、边框、主操作、成功、警告和错误；明确明暗主题下的语义映射，不在各页重复硬编码颜色与字号。主次信息通过层级、留白和对比度表达，颜色不能是状态的唯一提示。
- 新建或重塑视觉体系时，先确定内容层级、使用场景和品牌约束，再选择字体、配色与布局。动画、渐变或装饰不能掩盖操作重点；对比度与焦点状态依据项目无障碍目标核验。

## 组件与开源方案

- 优先核查项目已安装的组件库与封装。缺少能力时，再查询候选库的官方文档、GitHub 仓库、目标 Vue 版本兼容性、维护状态、许可证、无障碍能力、主题定制与引入成本；不能仅凭 Star 数或示例截图决定采用。
- Element Plus 是 Vue 3 的候选组件库，可提供表单、弹窗及主题能力；项目若使用 Vue 2 或现有其他体系，应按对应版本和迁移成本选择。不要为一个控件并列引入多套职责重叠的组件库。
- 开源组件、图标和样式应遵循许可证与来源要求。复用其公开 API 和主题变量；若需大量依赖内部 DOM 结构或反复深层覆盖样式，应重新评估选型或封装边界。

## 交互与动效

- 有异步处理或副作用的操作应明确触发、进行中、成功、失败与适用的恢复方式。提交、删除和耗时操作提供及时反馈；动画用于解释状态或空间关系，不能代替结果提示。
- 转场与微动效遵循现有节奏并保持克制；避免连续、重复或阻断操作的动画。保证键盘与触控操作可用，减少动态效果偏好下提供低动态或无动画路径。
- 操作确认、撤销和错误恢复依据后果设计。对破坏性操作给出清晰对象与影响，不能仅依赖按钮颜色或动画表达风险。

## 验证

对照同模块既有页面核对组件状态、字体、颜色和间距；在目标尺寸与输入方式下检查布局、焦点、对比度、动画关闭及关键流程反馈。新引入依赖时记录版本、许可证、用途和实际验证的集成能力。
