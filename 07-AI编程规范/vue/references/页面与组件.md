# Vue 页面、组件与表单

适用范围：页面结构、组件契约、表单交互或模板渲染。采用 Vue 2/3、Options/Composition API 或组件库时，遵循目标项目已确认的版本与约定。

## 组件边界

- 组件承担明确的展示或交互职责。新增抽象前核查现有组件、组合函数和设计系统；同样外观不足以证明行为契约相同。
- 同一后端字段在多个页面出现时，核对其业务含义、单位、状态和值域。语义相同的显示名称、格式和选项从已有字段定义或展示映射复用；语义确有差异时按页面上下文命名，不能仅为消除重复而强制统一。后端字段名不直接充当界面文案。
- 明确 props、事件及双向绑定的输入输出语义。输入数据的归属和修改方式遵循所用 Vue 版本；派生值优先表达为可追溯的计算结果，有副作用的侦听需处理重复执行与失效清理。
- 列表使用稳定且唯一的业务键；分页、筛选和视图切换时核对组件状态是否被错误复用。弹窗、表单和页面离开时清理仅属于该实例的订阅与异步副作用。

## 交互与安全

- 表单按当前需求及接口契约校验必填、格式、范围、长度和跨字段关系；在发送请求前拦截明确无效的输入，并给出字段级反馈。校验须覆盖实际提交值，不能只限制输入控件。数量、价格、权限和状态迁移等权威规则仍由后端核验；前端禁用提交按钮不提供请求幂等保证。
- 加载、空数据、失败、处理中和成功状态应与实际请求结果对应。失败时保留可恢复的输入，避免重复提交或将旧数据误显为新结果。
- 文本由框架安全插值渲染；使用原始 HTML、外部 URL 或第三方内容时核查信任来源和渲染风险，不将用户输入直接编译为模板。
- 按现有交互体系保留键盘操作、可见焦点、字段标签、错误提示与状态反馈。图标或颜色不得成为传达关键状态的唯一方式。

## 验证

按变更范围覆盖同字段跨页面展示、合法与无效输入、拦截后的请求数量、异步成功与失败、重复操作、组件复用及键盘交互。仅视觉呈现变更时按影响选择验证，不自动引入全部接口或后端测试。
