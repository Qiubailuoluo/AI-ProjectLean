# Vue 页面组织与复用

适用范围：重复组件或样式、单文件职责混杂、跨页面展示不一致，或长流程因局部补丁持续膨胀。依据现有设计系统、模块边界和真实重复行为决定抽取范围；文件行数仅是检查信号，不构成强制拆分阈值。

## 组件与展示语义

- 修改前搜索同模块和共享目录中的现有组件、组合函数、字段展示映射及样式变量。比较输入、输出、状态、交互和权限条件；契约相同时复用或扩展既有实现。
- 多个页面重复的结构与交互可抽成组件，变化部分通过明确的 props、事件或 slot 表达；页面特有的业务分支留在页面或所属模块。避免把所有差异做成大量布尔开关或创建职责过宽的通用组件。
- 同一业务字段的显示名称、单位、枚举说明和格式在语义一致时集中维护；页面用途不同可用有依据的上下文文案。调整映射时检查列表、详情、表单、导出入口和无障碍标签，不只修改当前截图。

## 样式与文件边界

- 同模块重复的字号、字重、间距、颜色和交互状态，复用项目既有设计令牌、CSS 变量、SCSS 变量或模块样式。令牌按职责命名，不用页面位置或偶然数值命名。
- 组件局部样式保留在组件范围；模块共用样式集中到既有样式入口。`scoped` 限定选择器影响范围，不自动实现跨组件复用；避免用层层 `:deep()` 覆盖组件库内部结构维持一致性。
- 单文件同时承载大量 API 调用、状态编排、纯计算、复杂模板和重复样式时，按职责拆分：视图与交互留在 `.vue`，稳定业务数据访问放现有 API 层，可复用的有状态逻辑放项目支持的组合函数或等效机制，纯函数放适当模块，样式按复用范围归属。抽取后保留清晰的数据流与生命周期清理。
- 不因文件超过固定行数拆分，也不为每个方法新建文件。拆分应减少重复、降低修改影响面，并让调用方更容易定位行为。

## 长流程与局部重构

- 变更流程前追踪入口、状态变化、请求、错误处理与退出路径；识别重复分支、隐式共享状态和每次修改都会触碰的节点。
- 在本次需求范围内，优先整理清晰的步骤、状态归属和失败恢复，再接入新行为。若最小补丁会进一步复制规则或扩大条件链，应完成必要的局部重构；跨模块架构调整需另有需求或证据。
- 区分需求要求的行为变化与结构整理；纯重构部分保留原有接口、可见行为及权限边界。注释记录非显然的状态约束与设计原因，不为旧补丁保留失效说明。

## 验证

核对抽取前后的页面显示、交互状态、共享组件调用方、模块样式和主要流程分支。校验无效输入不会发出请求，失败后状态可恢复；对局部重构记录实际覆盖与未覆盖的调用路径。
