# 知识库约定

更新：2026-10-31

- 顶层面向软件开发学习，Spring Boot 是 Java 后端下的一条路线。
- 使用“总纲 → 章节入口 → 专题/示例 → 配套导图”。章节主笔记保留主线；篇幅过长或专题需要扩展时，可自行创建子文件夹拆分，并从章节入口链接，避免碎片化和单篇过度膨胀。
- 通用知识维护一份，通过链接关联具体技术实践。
- 章节说明为什么、职责、示例、适用条件、风险与待深入项；不逐条复制聊天。
- 课程的问答、理解检查、个人复盘和薄弱点，放在对应路线下独立的 `90-复盘与问答/` 文件夹。顶层 `90-学习协作记录/` 维护协作约定、阶段交接及记录入口；章节正文专注知识内容，确需纠错或补充说明时才修改，不把每轮测评写进章节。学习路线保留资料导航与简短阶段说明，详细个人评估放入复盘记录。
- 默认先将当前章节或完整专题整理成可连续阅读的 Obsidian 文档，用户自行通读后带具体疑问讨论，再补充笔记；不再以每次一小段、逐段等待确认的方式推进。保留基础解释，不以加快节奏为由跳过前置概念。
- 区分通用概念、当前采用的约定和特定框架机制，不把个人习惯写成唯一标准。
- 代码示例如不完整，要明确是示意，不宣称可直接运行。
- 一个章节讨论完成后及时落盘，无需等整条路线完成；同步维护学习地图与交接记录。
- 可自行维护合理的子目录和记录。明显改变顶层体系时与用户讨论。
- 不把“已讨论”写成“已掌握”；区分讨论、整理和实践验证。
- 主动编写但尚未与用户讨论的内容标为“已整理，待阅读/答疑/实践”，不能写成“用户已经理解”或“章节已完成”。
- 导图跟随章节组织；XMind 与详细笔记互补，不要求每个小主题都建导图。导图应保留具体结论、判断条件、步骤、例子和常见误区，不能只复制章节目录。原生 XMind 保存整章可折叠树；Obsidian 按主题拆分 Mermaid 图，兼顾细节与可读性。
- 笔记使用 Obsidian 双链；文件名尽量唯一。附件按路线归档。
- 同一路线的附件分为 `导图大纲/` 与 `XMind思维导图/` 两个主文件夹，分别存放供 Obsidian 阅读的 Mermaid 导图笔记和可用 XMind 直接打开的原生 `.xmind` 文件。Markdown 导入源稿保留在 `导图大纲/XMind导入大纲/`；移动时保留唯一文件名，维持双链。章节更新时同步维护正文、大纲与原生导图，不能只交付 Markdown 导入稿。
- 可复制的 Skill 放根目录 `07-AI编程规范/`，优先只维护一份自包含文件夹，使用普通相对链接。工程内容是可适配参考：打包、构建、目录、命名与格式允许服从项目需要，关键正确性边界按业务保障。AI 根据当前工具识别适合的项目级接入方式，按项目栈与任务范围选择参考文件；不要求必填模板、生成副本或打包工具。项目副本可裁剪无用规范，但不据此移除应用源码、数据或实际使用但规范待补的技术。
- 保留用户现有资料和应用配置，避免无关修改。

## 新 AI 接手顺序

先读本文件、[[学习者背景与偏好]]、[[学习进度与交接]]，再读当前章节与路线。后续更新只记录可供继续工作的事实、结论和偏好，不记录模型内部推理。

## 章节文件组织

- 每章使用一个文件夹，章节入口位于文件夹内，以 `00-章节名.md` 命名；不在父目录再保留同名主笔记。
- 专题使用 `01-专题名.md` 等有序文件名，章节入口维护阅读顺序与摘要。
- 不同章节的入口名称保持唯一，不都命名为“README”或“章节导读”，减少双链歧义。
- 第一章拆为四个连贯专题；第二章保留章节正文与独立案例，按内容需要继续拆分，不为形式对称强制拆分。
