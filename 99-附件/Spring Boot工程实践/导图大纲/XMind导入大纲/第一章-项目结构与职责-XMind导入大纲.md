# 第一章：项目结构与职责
## 分层为什么存在
### 按变化原因分配职责
#### 请求字段变化主要影响接口输入
#### 满减规则变化属于业务逻辑
#### SQL 优化属于数据访问
### 不同入口复用同一业务
#### HTTP 与定时任务都可调用订单业务入口
#### 不把下单规则全部写在 Controller
### 分层不是固定数量的类
#### 简单项目不强制每层再包一层
#### 判断变化归属，不只看目录名字
## 各部分负责什么
### Controller 连接 HTTP 与业务
#### 接收参数、触发校验、取得当前身份
#### 调用 Service 并组织接口响应
### Service 执行业务规则
#### 商品是否可售、金额怎样算、订单怎样生成
#### 协调模块与必要的事务边界
### Mapper 访问数据库
#### 查询商品、条件更新库存、插入订单
#### 不自行决定前端怎样弹窗
### 技术组件提供能力
#### Config 配置连接，存储组件封装 MinIO
#### 业务决定缓存策略、上传用途与权限
## 校验与并发保障
### 输入校验
#### 商品 ID 非空，购买数量大于零
#### DTO 注解需依赖与触发方式配合
### 业务校验
#### 商品存在且可售，需要读取系统状态
#### 每人限购，需要结合购买记录
### 内部入口也要有前提
#### 定时任务调用 Service 不会天然经过 HTTP 校验
#### 关键业务不变量不能只靠页面保护
### 查询库存不等于扣减成功
#### 库存为一，两人可能都查到充足
#### 可靠扣减需条件更新等并检查结果
## 目录与模块边界
### 当前优先业务包在外
#### order 和 product 内部各放技术层
#### 改一个业务时尽量集中定位相关代码
### 源码、资源与测试
#### Java 源码与 resources 各有位置
#### Mapper 接口与 XML 共同承担数据访问
### 业务包不是部署单元
#### 多个业务包可共用一个 pom.xml
#### 包分开不等于 Maven 多模块或微服务
### 公共代码要有公共职责
#### 统一响应与通用异常可以共享
#### 不把所有业务规则塞进 common 或 RedisUtils
## Service 组织与模块协作
### 接口与方法拆分是独立选择
#### 单实现可以直接用具体 Service
#### 不为形式建立空接口和空转发
### 主方法表达流程
#### 查商品、算金额、扣库存、存订单
#### private 方法可封装内部细节
### Request 与 Command 分开职责
#### Request 接收商品 ID 与购买数量
#### Command 还可包含认证取得的买家 ID
#### Controller 组装后交给 Service
### 接口形式变化可在转换处适配
#### buyCount 映射到 Command 的 quantity
#### Service 不必依赖 HTTP 字段命名
### 业务变化仍需调整业务输入
#### 新增优惠券可能同时改变 Command 与 Service
#### Command 不会自动隔离全部变化
### DTO 是宽泛称呼，Command 按业务意图命名
#### Request 与 Command 都可以承担传输数据的作用
#### 简单项目输入长期一致时可以不拆分
### 公开方法需要契约
#### 明确输入、输出、业务规则和失败条件
#### getById 不自动承诺已经检查可售状态
### 跨模块通过明确能力协作
#### 订单调用商品业务入口，再由商品访问 Mapper
#### 同一应用通常是 Java 调用，不必改用 HTTP
### 拆方法不自动改变事务
#### 类内自调用不会新增事务代理拦截
#### 已有外层事务时内部步骤仍可参与
## 对象边界与交易快照
### CreateOrderRequest 限制输入
#### 客户端表达商品和数量
#### 买家身份与成交金额不能随意自报
### OrderEntity 表达持久化
#### 表字段不等于全部允许客户端修改
#### Entity 也不默认全部允许对外返回
### OrderResponse 决定公开数据
#### 只返回接口所需字段
#### 排除内部成本、备注等不应公开信息
### ProductPurchaseInfo 表达模块契约
#### 商品提供购买需要的数据，而非整份 Entity
#### record 只是示例，需匹配 Java 版本
### 订单保存成交快照
#### 保存成交名称、单价与数量等历史事实
#### 商品改价后不重算历史订单金额
### ApiResponse 是响应外壳
#### code 和 message 外包裹业务 data
#### 统一外壳不要求所有 HTTP 状态都为 200
## 阅读与实践边界
### 已讨论与整理基础主线
#### 不等于已经熟练掌握
#### 尚未通过真实项目验证
### 检查 AI 代码的重点
#### 职责、依赖、输入边界与历史事实
#### 防止为形式增加无意义对象和方法
