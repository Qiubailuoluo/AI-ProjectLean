# 第二章：接口设计与数据流转

## 接口表达业务意图
### 请求提交商品与数量
### 后端决定身份、金额与状态
### 查不到可信数据应明确失败
## Controller 衔接请求与业务
### JSON 转换与输入校验
### 获取认证身份
### 调用业务并组织响应
## DTO 与 Command
### 简单单入口可直接使用 DTO
### 多入口或独立变化时考虑 Command
### 不为形式增加重复对象
## 失败处理
### 输入错误
### 业务失败
### 系统故障
### 统一响应不负责事务回滚
## HTTP 状态与业务码
### 状态表达结果类别
### 业务码表达具体原因
### code 稳定，message 可调整
### 统一规则，模块维护业务码
## 身份与权限
### 凭证验证
### 功能权限
### 具体数据权限
### 业务状态限制
### 安全框架有自己的失败处理入口
## 创建订单的四种结果
### 参数非法：400
### 商品下架：409
### 创建成功：201
### 系统故障：500
